🔗 Redis Connection Management

Anti-Pattern (SEBELUM)

// Connection leak: membuat koneksi BARU setiap request
pub async fn allow(&self, key: &str) -> Result<bool> {
    let mut conn = self.client
        .get_multiplexed_async_connection()  // TCP connection baru!
        .await?;
    // ... use conn
}

Best Practice (SESUDAH)

// ConnectionManager lazy-init via Arc + Mutex
struct LimiterInner {
    client: redis::Client,
    conn: Mutex<Option<ConnectionManager>>,
}
impl LimiterInner {
    async fn get_conn(&self) -> Result<ConnectionManager> {
        let mut guard = self.conn.lock().await;
        if let Some(conn) = guard.as_ref() {
            return Ok(conn.clone());
        }
        let conn = self.client.get_connection_manager().await?;
        guard.insert(conn.clone());
        Ok(conn)
    }
}
Prinsip: ConnectionManager dari redis-rs sudah menyediakan connection pooling built-in via fitur connection-manager. Cukup init sekali, clone untuk reuse.
  • get_multiplexed_async_connection() = buat koneksi baru setiap kali
  • get_connection_manager() = pool dengan multiplexing
  • Gunakan Arc<Mutex<Option<ConnectionManager>>> untuk lazy init
  • ConnectionManager::clone() sangat ringan (reference clone)

🔗 gRPC Channel Management

// Arc<ManagedChannel> reuse + concurrent send
struct NotificationClient {
    channel: Arc<Channel>,
}
pub async fn send_bulk(&self, recipients: &[String], msg: &Message) {
    let mut handles = Vec::new();
    for user_id in recipients {
        let channel = self.channel.clone();
        let msg = msg.clone();
        handles.push(tokio::spawn(async move {
            let mut client = NotificationServiceClient::new(channel);
            client.send(msg).await
        }));
    }
    for h in handles { h.await.ok(); }
}
Perhatian: Untuk 10K+ recipients, tokio::spawn per recipient bisa memberatkan scheduler. Pertimbangkan batching (group per 100) jika ada performance issue.

🧠 Memory Leak Prevention

MEDIUM
HashMap entry tidak pernah di-remove
chat-service/ws_handler.rs

conversation_rooms adalah Arc<DashMap<String, broadcast::Sender>> yang terus bertambah. Entry tidak terpakai tetap berada di map setelah user disconnect.

// Setelah user disconnect, cek receiver_count
if tx.receiver_count() == 0 {
    conversation_rooms.remove(&conversation_id);
    tracing::info!("cleaned up empty channel: {conversation_id}");
}
  • Setiap HashMap/DashMap yang menyimpan koneksi harus punya cleanup logic
  • Gunakan weak references atau receiver_count() untuk deteksi unused
  • broadcast::Sender::receiver_count() = 0 semua receiver sudah disconnect

🔄 Graceful Shutdown

// Connections.ts — shared connection management
import { Redis } from "ioredis";
import { Pool } from "pg";

export const redis = new Redis(process.env.REDIS_URL);
export const pool = new Pool({ connectionString: process.env.DATABASE_URL });

export async function shutdown_connections() {
    await redis.quit();       // Drain Redis
    await pool.end();         // Drain DB pool
    transporter.close();      // Close SMTP
}

// index.ts — SIGTERM handler
process.on('SIGTERM', async () => {
    await shutdown_connections();
    process.exit(0);
});

⚡ N+1 Query Prevention

MEDIUM
region-service get_by_id — 4 sequential queries
region-service/pg_repository.rs

4 sequential queries (village, district, regency, province) jadi 1 UNION ALL:

let row: Option<(String, String, String)> = sqlx::query_as(
    r#"SELECT id, name, 'village' FROM region.village WHERE id = $1
       UNION ALL
       SELECT id, name, 'district' FROM region.district WHERE id = $1
       UNION ALL
       SELECT id, name, 'regency' FROM region.regency WHERE id = $1
       UNION ALL
       SELECT id, name, 'province' FROM region.province WHERE id = $1
       LIMIT 1"#,
).bind(id).fetch_optional(&self.pool).await?;

Hasil: 4 round-trip → 1 round trip

📄 Pagination Best Practice

-- Single query dengan COUNT(*) OVER() untuk total count
SELECT id, title, price,
       COUNT(*) OVER() AS total_count
FROM iklan_pekerjaan
WHERE deleted_at IS NULL
ORDER BY created_at DESC
LIMIT $1 OFFSET $2

Semua service iklan sudah pakai pattern ini. 1 round trip, tidak ada N+1 untuk pagination.
