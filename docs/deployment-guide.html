📦 Rejki — Deployment Guide

Panduan step-by-step untuk mendeploy Rejki Backend (Rust) + Rejki Web (Vue 3) ke VPS.
Images di-push ke GitHub Container Registry (GHCR) — server hanya pull & restart.

ghcr.io docker compose cloudflare tunnel postgres redis

💡
Kenapa pakai GHCR? Kenapa tidak clone repo di server?

Tidak clone repo di server — lebih aman, tidak ada source code di VPS.
Tidak build di server — server tidak perlu Rust toolchain (hemat 1-2GB).
Deploy lebih cepat — pull image jauh lebih cepat daripada build dari source.
Reproducible — image yang di-push sudah terverifikasi oleh CI.

Cara buat GHCR_TOKEN:

  2. Buat token baru dengan scope: read:packages
  3. Copy token dan simpan sebagai secret GHCR_TOKEN di repo

Repositori mana yang perlu secrets?

Kedua repo: rejki-backend dan rejki-web. Secrets-nya SAMA (VPS yang sama). Untuk web repo, GHCR_TOKEN hanya butuh scope read:packages — CI build pakai GITHUB_TOKEN built-in.

3 Setup GitHub Container Registry

GitHub Container Registry (GHCR) adalah tempat penyimpanan Docker images. Ini otomatis aktif untuk akun GitHub.

3.1 Aktifkan GHCR untuk repo

  1. Buka repo di GitHub → Settings → Actions → General → Workflow permissions
  2. Pilih: Read and write permissions
  3. Centang: Allow GitHub Actions to create and approve pull requests

3.2 Verifikasi image sudah terpush

Setelah CI pertama jalan, image akan muncul di:
https://github.com/orgs/rejki/packages atau sidebar repo → Packages.

4 Setup SSH Key untuk GitHub Actions

GitHub Actions perlu akses SSH ke VPS untuk menjalankan perintah deploy.

4.1 Generate SSH key pair (di VPS atau lokal)

ssh-keygen -t ed25519 -C "github-actions-deploy" -f ~/.ssh/github-actions
# Ini menghasilkan 2 file:
#   ~/.ssh/github-actions      (private key)
#   ~/.ssh/github-actions.pub  (public key)

4.2 Tambahkan public key ke VPS

# Di VPS:
cat ~/.ssh/github-actions.pub >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys

4.3 Tambahkan private key ke GitHub Secrets

  1. Copy isi file private key: cat ~/.ssh/github-actions
  2. Buka repo → Settings → Secrets and variables → Actions
  3. Buat secret baru: VPS_SSH_KEY → paste private key
⚠️
Format private key harus tepat

Pastikan private key diawali dengan -----BEGIN OPENSSH PRIVATE KEY----- dan diakhiri -----END OPENSSH PRIVATE KEY-----. Jangan ada spasi ekstra.

5 Deploy Infrastructure

Infrastructure (PostgreSQL, Redis, MinIO, ClamAV) adalah shared component yang digunakan oleh dev dan prod.

💡
Infrastructure cukup di-deploy SEKALI

PostgreSQL, Redis, dan MinIO di-deploy sekali di awal. Tidak perlu di-deploy ulang setiap update backend.

5.1 Buat direktori infrastructure

sudo mkdir -p /opt/rejki/{infra,dev,prod,keys,scripts}
sudo chown -R $USER:$USER /opt/rejki

5.2 Copy file docker-compose infrastructure

File docker-compose.infra.yml ada di repo backend. Copy ke server:

# Dari lokal, SCP file infra ke server:
scp docker-compose.infra.yml user@vps:/opt/rejki/infra/docker-compose.infra.yml

# Atau buat manual di server:
nano /opt/rejki/infra/docker-compose.infra.yml
# Paste dari isi docker-compose.infra.yml (base — postgres, redis, minio, clamav)

5.3 Buat file .env infrastructure

nano /opt/rejki/infra/.env

Isi dengan:

POSTGRES_PASSWORD=<password-kuat-random>
MINIO_ACCESS_KEY=<access-key-kuat>
MINIO_SECRET_KEY=<password-kuat-random>

5.4 Setup JWT keys

# Generate RS256 key pair (jika belum punya)
openssl genpkey -algorithm RSA -out /opt/rejki/keys/private.pem -pkeyopt rsa_keygen_bits:2048
openssl rsa -pubout -in /opt/rejki/keys/private.pem -out /opt/rejki/keys/public.pem
chmod 600 /opt/rejki/keys/*.pem

5.5 Start infrastructure

cd /opt/rejki/infra
docker compose --env-file .env up -d

# Verifikasi semua service running
docker compose ps

# Test PostgreSQL
docker compose exec postgres pg_isready -U rejki

# Test Redis
docker compose exec redis redis-cli ping
✅
Verifikasi Step 5

docker compose ps → postgres, redis, minio, clamav semuanya Up.

7.2 Dockerfile (Vue 3 + Bun + Nginx)

    
Web menggunakan multi-stage build dengan Bun: Stage 1 build Vue app, Stage 2 serve via Nginx dengan API proxy + security headers. Ini adalah Dockerfile di root rejki-web:


    
# rejki-web/Dockerfile
# Stage 1: Build dengan Bun
FROM oven/bun:1.3 AS build
WORKDIR /app
COPY package.json bun.lock ./
RUN bun install --frozen-lockfile
COPY . .

# Build arguments — Vite environment variables
ARG VITE_API_BASE_URL=/api/v1
ARG VITE_MAX_EVIDENCE_BYTES=5242880
ENV VITE_API_BASE_URL=${VITE_API_BASE_URL}
ENV VITE_MAX_EVIDENCE_BYTES=${VITE_MAX_EVIDENCE_BYTES}
RUN bun run build

# Stage 2: Serve via Nginx
FROM nginx:1.27-alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80

HEALTHCHECK --interval=15s --timeout=5s --retries=3 \
    CMD wget -qO- http://localhost:80/ || exit 1

CMD ["nginx", "-g", "daemon off;"]


    
File nginx.conf — Nginx config: API proxy ke backend + security headers + SPA routing:

    
# rejki-web/nginx.conf
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    # Gzip compression
    gzip on;
    gzip_types text/plain text/css application/json application/javascript image/svg+xml;
    gzip_min_length 1024;

    # Security headers
    add_header X-Content-Type-Options  "nosniff"                   always;
    add_header X-Frame-Options         "DENY"                      always;
    add_header Referrer-Policy         "strict-origin-when-cross-origin" always;

    # API proxy → rejki-app backend
    location /api/ {
        proxy_pass         http://rejki-app:8080;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_connect_timeout 5s;
        proxy_read_timeout    30s;
    }

    # SPA fallback — semua route ke index.html (Vue Router)
    location / {
        try_files $uri $uri/ /index.html;
    }
}


    

      🔄
      
Kenapa ada API proxy di nginx.conf web?
      
Nginx di container web berfungsi ganda: serve file static + reverse proxy ke backend. Ini memungkinkan web diakses via /api/ tanpa CORS issues. Di production VPS, Nginx reverse proxy (compose backend) ada di depannya dan merge traffic — jadi kedua layer Nginx bekerja bersama.

    


    
    
7.3 CI/CD Workflow (GitHub Actions)

    
Web menggunakan 3 file workflow terpisah — CI build+push, deploy dev, deploy prod — untuk pemisahan concern dan mencegah race condition:


    
7.3a CI — Build & Push Image (ci.yml)

    
Trigger: push ke develop atau main, atau PR. Menggunakan Bun, GITHUB_TOKEN built-in, dan Docker Buildx caching:


    
# rejki-web/.github/workflows/ci.yml
name: CI

on:
  push:
    branches: [develop, main]
  pull_request:

7.4 Nginx Routing — Dua Layer

    
Arsitektur menggunakan dua layer Nginx:


    

      
LayerLokasiFungsiDev vs Prod

      
        
Layer 1 — Web internalrejki-web/nginx.conf (di-bake ke image)Serve static + API proxy + security headers🟢 SAMA (via Dockerfile yang sama)

        
Layer 2 — VPS reverse proxy/opt/rejki/{dev,prod}/nginx.confReverse proxy ke semua container per environment🔴 BERBEDA (container hostname berbeda)

      
    


    
Di VPS, traffic dari Cloudflare Tunnel masuk ke Nginx container Layer 2 yang berfungsi sebagai reverse proxy. Nginx meneruskan request berdasarkan environment:


    

      
PathDev → ContainerProd → Container

      
        
/api/*rejki-app-dev:8080rejki-app-prod:8080

        
/notification/*rejki-bun-dev:9000rejki-bun-prod:9000

        
/* (HTML/JS/CSS)rejki-web-dev:80rejki-web-prod:80

      
    


    
Dev — /opt/rejki/dev/nginx.conf (Layer 2)

    
# /opt/rejki/dev/nginx.conf — Reverse proxy (listen port 8081)
server {
    listen 8081;
    server_name _;

    # API → rejki-app-dev
    location /api/ {
        proxy_pass http://rejki-app-dev:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    # Notification → bun-dev
    location /notification/ {
        proxy_pass http://rejki-bun-dev:9000;
        proxy_set_header Host $host;
    }

    # Web Dashboard → rejki-web-dev
    location / {
        proxy_pass http://rejki-web-dev:80;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_buffering off;
    }
}


    
Prod — /opt/rejki/prod/nginx.conf (Layer 2)

    
# /opt/rejki/prod/nginx.conf — Reverse proxy (listen port 8082)
server {
    listen 8082;
    server_name _;

    # API → rejki-app-prod
    location /api/ {
        proxy_pass http://rejki-app-prod:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    # Notification → bun-prod
    location /notification/ {
        proxy_pass http://rejki-bun-prod:9000;
        proxy_set_header Host $host;
    }

    # Web Dashboard → rejki-web-prod
    location / {
        proxy_pass http://rejki-web-prod:80;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_buffering off;
    }
}


    

      🔀
      
Alur request lengkap (contoh: dev)
      

        Browser → HTTPS dev.rejki.id → Cloudflare Tunnel → localhost:8081 (VPS nginx) → rejki-web-dev:80 (web nginx)

        API call: Browser → ... → rejki-app-dev:8080 (backend)

        Web container punya API proxy sendiri (/api/ → rejki-app:8080) tapi di VPS request /api/ sudah di-intercept oleh Layer 2 nginx, jadi biasanya langsung ke backend tanpa lewat web container.

#   Name: dev-obs
#   Scopes: centang semua (metrics:write, logs:write, traces:write, profiles:write, stacks:read)
#   → Klik "Create token"

# Copy 3 nilai:
#   Endpoint: https://otlp-gateway-prod-ap-southeast-2.grafana.net/otlp

# ── 3. Setup Loki (Logs) ─────────────────────────────────────────────────────
# Sidebar: Loki → Send logs → Pilih "Docker" atau "Generic"
# Copy 3 nilai:
#   URL:  https://logs-{zone}.grafana.net/loki/api/v1/push
#   User: {instance_id}
#   Token: glc_xxxxxxxxxxxx

# ── 4. Encode credentials ─────────────────────────────────────────────────────
# Format: "InstanceID:APIToken" → base64
# GRAFANA_OTEL_AUTH_HEADER = Authorization=Basic $(echo -n "1699861:glc_xxxxxxxxxxxx" | base64 -w0)
echo -n "12345:glc_xxxxxxxxxxxx" | base64

# ── 5. Buat folder observability & isi .env ──────────────────────────────────
cd /opt/rejki/dev/rejki-backend
cp observability/.env.example observability/.env
nano observability/.env

# Contoh isi .env (isi dengan data dari Grafana Cloud):
# GRAFANA_OTEL_ENDPOINT=https://otlp-gateway-prod-ap-southeast-2.grafana.net/otlp
# GRAFANA_OTEL_AUTH_HEADER=Authorization=Basic MTY5OTg2MTpnbGNfeHh4eHh4eHh4eHh4
# GRAFANA_LOKI_URL=https://logs-{zone}.grafana.net/loki/api/v1/push

# GRAFANA_LOKI_TOKEN=glc_xxxxxxxxxxxx
# POSTGRES_PASSWORD=isi_sesuai_env_prod

# ── 6. Start Observability Stack ────────────────────────────────────────────
docker compose -f observability/docker-compose.yml -p rejki-obs up -d

# ── 7. Verifikasi ───────────────────────────────────────────────────────────
docker compose -f observability/docker-compose.yml -p rejki-obs ps

# node-exporter, cadvisor, postgres-exporter, redis-exporter,
# otel-collector, alloy

# ── 8. Buka Grafana Cloud Dashboard ─────────────────────────────────────────
# Grafana → Explore:
#   - Metrics: pilih "Mimir/Prometheus" → cari "node_cpu", "container_memory"

#   - Traces: pilih "Tempo" → cari service.name="rejiki-backend-prod"
💡
Catatan Penting

1. Observability stack jalan sebagai compose project terpisah (rejki-obs) — tidak perlu restart dev/prod.
2. Rust app dev & prod otomatis kirim traces ke rejki-otel-collector:4317 (via internal network rejki-infra).
3. Cukup aktifkan OTEL headers di dev/prod .env: OTEL_EXPORTER_OTLP_HEADERS=Authorization=Basic {base64}
4. Log shipping via Alloy otomatis — semua container stdout terkumpul ke Loki.
5. Node Exporter & cAdvisor perlu akses ke host filesystem (--volume /:/host) — itu normal.

🔒Security & Permission

🛡️ Ringkasan Keamanan

LapisanKonfigurasi
FirewallHanya port SSH (22) yang terbuka. Semua port aplikasi bind ke 127.0.0.1.
IngressCloudflare Tunnel — zero-trust, koneksi outbound dari VPS. Tidak ada port 80/443 terbuka.
DatabasePostgreSQL hanya listen di 127.0.0.1:5432. Authentication via password.
RedisRedis hanya listen di 127.0.0.1:6379. Tanpa auth (hanya internal).
MinIOMinIO hanya listen di 127.0.0.1:9000. Access key + secret key.
File PermissionDirektori /opt/rejki dimiliki user rejki:rejki. Kunci privat 600.
SSHHanya key-based authentication. Password login disabled.
JWTRS256 (asymmetric). Private key hanya di VPS. Public key di container.
EncryptionAES-256-GCM untuk data sensitif (phone, rekening). Key di .env.
Rate Limiting3 zona: umum (10r/s), auth (3r/s), strict (1r/s). Custom 429 response.
Virus ScanClamAV di production untuk semua upload dokumen.

🔧Troubleshooting

🔄

Container restart loop

Cek log: docker logs [container-name] --tail 50. Biasanya karena environment variable tidak terisi atau database belum siap.

LogEnv
🔌

Cannot connect to database

Pastikan container rejki-postgres ada di network yang sama: docker network inspect rejki-infra. Cek juga POSTGRES_PASSWORD di .env.

NetworkDatabase
🌐

Cloudflare Tunnel error

Cek docker logs rejki-tunnel. Pastikan TUNNEL_TOKEN valid. Cek juga DNS record di Cloudflare Dashboard.

TunnelDNS
💥

Out of memory (OOM)

VPS 2GB — matikan dev jika prod sedang sibuk. Cek docker stats untuk melihat memory usage realtime. Jika perlu, kurangi memory limit ClamAV.

MemoryOOM
🔑

GitHub Actions SSH failed

Verifikasi: (1) Public key ada di authorized_keys, (2) Permission file 600, (3) User rejki punya home /opt/rejki/.ssh, (4) Private key di GitHub Secrets format PEM.

SSHGitHub
🧪

Migration failed

Pastikan sqlx-cli terinstall: cargo install sqlx-cli. Cek juga DATABASE_URL sudah benar (dev → rejki_dev, prod → rejki_prod).

MigrationSQL
