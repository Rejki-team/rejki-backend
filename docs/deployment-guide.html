Rejki Backend & Web
Deployment Guide

Panduan lengkap deployment Rejki Backend (Rust modular monolith + Bun notification service) dan Rejki Web (Vue 3 SPA) ke 1 VPS (2 vCPU, 2 GB RAM) dengan dua environment (dev + prod) yang berbagi database dan Redis.

🖥️ Single VPS 🐳 Docker Compose ⚙️ GitHub Actions 🔒 Cloudflare Tunnel

🏗️Arsitektur Deployment

Satu VPS berisi 3 Compose Project yang berjalan bersamaan. Dev dan prod berbagi PostgreSQL, Redis, dan MinIO yang sama, namun menggunakan database name dan Redis DB index yang berbeda.

VPS — 2 vCPU · 2 GB RAM
┄┄┄ Shared Infrastructure (docker-compose.infra.yml) ┄┄┄
PostgreSQL 17port 5432 · db: rejki_dev + rejki_prod
Redis 7port 6379 · DB 0 (dev) + DB 1 (prod)
MinIOport 9000 · bucket terpisah
┄┄┄ Dev Environment (docker-compose.dev.yml — port 8081) ┄┄┄
rejki-app-devRust · port 8080 · debug mode
rejki-bun-devBun · port 9000

┄┄┄ Production Environment (docker-compose.prod.yml — port 8082) ┄┄┄
rejki-app-prodRust · port 8080 · release mode
rejki-bun-prodBun · port 9000
rejki-web-prodVue 3 · nginx internal
nginx-prodReverse proxy · port 8082
ClamAVVirus scan · hanya prod

Cloudflare TunnelZero-trust ingress
🔗 Semua container terhubung ke network rejki-infra (external) + network internal per environment
💡
Kenapa Dev & Prod di VPS yang sama?

Keduanya berbagi PostgreSQL, Redis, dan MinIO untuk menghemat resource. Database terpisah (rejki_dev / rejki_prod), Redis DB index terpisah (0 / 1), dan MinIO bucket terpisah memastikan data tidak tercampur.

✅
Kenapa hanya 4 secrets?

Semua environment variables disimpan di file .env di VPS, bukan di GitHub Secrets. Ini karena setiap env (dev/prod) punya nilai berbeda. GitHub Actions hanya perlu akses SSH untuk menjalankan perintah di VPS.

⚠️
File .env jangan di-commit!

File .env.dev.example dan .env.prod.example adalah template. Copy ke /opt/rejki/dev/.env dan /opt/rejki/prod/.env, isi nilai sebenarnya, dan pastikan .env ada di .gitignore.

⚙️Setup GitHub Secrets

Buka repository GitHub → Settings → Secrets and variables → Actions → New repository secret. Tambahkan 4 secrets berikut:

SecretNilaiCara Mendapatkan
VPS_HOST IP address VPS Lihat di dashboard provider VPS (contoh: 103.xx.xx.xx)
VPS_USER rejki Dibuat oleh setup-vps.sh
VPS_SSH_KEY Private key SSH Generate:
ssh-keygen -t ed25519 -C "github-actions" -f ~/.ssh/rejki-deploy
Paste ~/.ssh/rejki-deploy.pub ke /opt/rejki/.ssh/authorized_keys di VPS
Copy ~/.ssh/rejki-deploy (private key) ke GitHub Secrets
VPS_PORT 22 Default, bisa diganti jika SSH di port lain
⚠️
SSH Key Permission

Private key yang di-paste ke GitHub Secrets harus format PEM. Pastikan file authorized_keys di VPS memiliki permission 600 dan dimiliki oleh user rejki.

💡
Dev juga via Cloudflare Tunnel!

Sekarang dev juga punya container tunnel sendiri di docker-compose.dev.yml. Di Cloudflare Dashboard, arahkan dev.rejki.id ke localhost:8081. Prod diarahkan ke localhost:8082. Token tunnel bisa sama (1 tunnel, beda hostname) — simpan di .env dev dan prod.

Dengan ini dev tetap bisa diakses meskipun prod compose dimatikan.

🖥️Setup VPS — 15 Langkah

Jalankan langkah-langkah ini setelah VPS pertama kali dibuat. Script otomatis setup-vps.sh mencakup langkah 1—8.

1

Update System

sudo apt-get update && sudo apt-get upgrade -y
2

Install Dependencies

sudo apt-get install -y ca-certificates curl gnupg lsb-release ufw git openssl
3

Install Docker Engine

# Tambah repo Docker
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list

sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo systemctl enable --now docker
4

Create User rejki

sudo useradd -m -d /opt/rejki -s /bin/bash rejki
sudo usermod -aG docker rejki    # biar bisa manage container tanpa root
5

Buat Directory Structure

sudo mkdir -p /opt/rejki/{dev,prod,keys,scripts}
sudo chown -R rejki:rejki /opt/rejki
6

Setup SSH untuk GitHub Actions

sudo mkdir -p /opt/rejki/.ssh
sudo chmod 700 /opt/rejki/.ssh
sudo touch /opt/rejki/.ssh/authorized_keys
sudo chmod 600 /opt/rejki/.ssh/authorized_keys
sudo chown -R rejki:rejki /opt/rejki/.ssh

Tambahkan public key dari step GitHub Secrets ke /opt/rejki/.ssh/authorized_keys.

7

Generate JWT Key Pairs

cd /opt/rejki/keys
openssl genrsa -out private.pem 2048
openssl rsa -in private.pem -pubout -out public.pem
chmod 600 private.pem
chown rejki:rejki *.pem
8

Generate Encryption Key

openssl rand -base64 32
# Copy output → isikan ke DATA_ENCRYPTION_KEY di .env file
9

Konfigurasi UFW Firewall

sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp comment 'SSH'
sudo ufw --force enable

Hanya port SSH yang terbuka. Semua traffic aplikasi masuk via Cloudflare Tunnel (koneksi outbound dari VPS).

10

Kernel Tweaks untuk VPS 2GB

sudo tee -a /etc/sysctl.conf << 'EOF'
# Rejki optimizations
net.core.somaxconn = 1024
net.ipv4.tcp_fastopen = 3
net.ipv4.tcp_tw_reuse = 1
vm.swappiness = 10
vm.vfs_cache_pressure = 50
EOF
sudo sysctl -p
11

Download Firebase Service Account

Download file JSON Firebase Admin SDK untuk dev dan prod project. Letakkan di /opt/rejki/keys/:

/opt/rejki/keys/
├── firebase-service-account-dev.json    # Firebase Dev project
└── firebase-service-account-prod.json   # Firebase Prod project
12

Clone Repository

# Clone untuk dev (branch develop)
sudo -u rejki git clone -b develop git@github.com:rejki/rejki-backend.git /opt/rejki/dev/rejki-backend

# Clone untuk prod (branch main)
sudo -u rejki git clone -b main git@github.com:rejki/rejki-backend.git /opt/rejki/prod/rejki-backend

Pastikan SSH key GitHub sudah disetup agar bisa clone via SSH.

13

Copy & Edit .env Files

# Dev
cp /opt/rejki/dev/rejki-backend/.env.dev.example /opt/rejki/dev/.env
nano /opt/rejki/dev/.env    # isi password, key, dll

# Prod
cp /opt/rejki/prod/rejki-backend/.env.prod.example /opt/rejki/prod/.env
nano /opt/rejki/prod/.env    # isi password, key, dll
14

Clone rejki-web

rejki-web adalah repo terpisah. Clone di kedua direktori, pastikan branch sesuai:

cd /opt/rejki/dev
git clone -b develop git@github.com:rizkirchm97/rejki-web-dashboard.git rejki-web

cd /opt/rejki/prod
git clone -b main git@github.com:rizkirchm97/rejki-web-dashboard.git rejki-web
15

Verifikasi Semua File

Pastikan struktur direktori sudah benar:

ls -la /opt/rejki/
# Harus ada: dev/ prod/ keys/ scripts/ .ssh/

ls -la /opt/rejki/keys/
# Harus ada: private.pem public.pem firebase-service-account-*.json

ls -la /opt/rejki/dev/.env
# Harus ada file .env

ls -la /opt/rejki/prod/.env
# Harus ada file .env

🐳Start Shared Infrastructure

Infrastructure (PostgreSQL, Redis, MinIO) dijalankan sebagai Compose Project terpisah. Dev dan prod akan connect ke network yang sama. 

cd /opt/rejki/dev/rejki-backend

# Buat network external (hanya sekali)
docker network create rejki-infra --driver bridge

# Start infrastructure container
docker compose -f docker-compose.infra.yml up -d

# Verifikasi semua container sehat
docker compose -f docker-compose.infra.yml ps

# Cek log — pastikan init-databases.sql sukses
docker logs rejki-postgres --tail 20
✅
Init-databases.sql akan otomatis:

Membuat database rejki_dev dan rejki_prod, semua schema (auth, user_svc, chat, notification, iklan_*, comms, report, storage, region, analytics, corporate_comms), dan grant semua hak akses ke user rejki.

Verifikasi Database

# Masuk ke container PostgreSQL
docker exec -it rejki-postgres psql -U rejki -d rejki_dev -c '\dn'
docker exec -it rejki-postgres psql -U rejki -d rejki_prod -c '\dn'

# Cek Redis
docker exec -it rejki-redis redis-cli ping
# Harus response: PONG

# Cek MinIO
curl -f http://localhost:9000/minio/health/live
# Harus response: ok

🧪Deploy Dev Environment

Dev environment jalan di port 8081 (localhost only). Bisa diakses via dev.rejki.id jika Cloudflare Tunnel dikonfigurasi. 

cd /opt/rejki/dev/rejki-backend

# Load .env dari parent directory
export $(grep -v '^#' /opt/rejki/dev/.env | xargs)

# Create docker network (sekali)
docker network create rejki-dev --driver bridge

# Build images
docker compose -f docker-compose.dev.yml -p rejki-dev build

# Start services
docker compose -f docker-compose.dev.yml -p rejki-dev up -d

# Verifikasi
sleep 10
docker compose -f docker-compose.dev.yml -p rejki-dev ps
curl -sf http://localhost:8081/health

# Cek log
docker compose -f docker-compose.dev.yml -p rejki-dev logs --tail 20

Migrate Database (Dev)

cd /opt/rejki/dev/rejki-backend
bash scripts/migrate.sh dev
💡
Dev Mode Features

RUST_LOG=debug — log lebih verbose. APP_ENV=development — Swagger/OpenAPI docs aktif. CORS di-set ke http://dev.rejki.id. Email dikirim via Mailtrap (tidak sampai ke user real).

🚀Deploy Production Environment

Production environment jalan di port 8082 dengan tambahan ClamAV, DB backup, dan Cloudflare Tunnel. 

cd /opt/rejki/prod/rejki-backend

# Load .env dari parent directory
export $(grep -v '^#' /opt/rejki/prod/.env | xargs)

# Create docker network (sekali)
docker network create rejki-prod --driver bridge

# Build images
docker compose -f docker-compose.prod.yml -p rejki-prod build

# Start services (dengan profile prod untuk cloudflare tunnel)
docker compose -f docker-compose.prod.yml -p rejki-prod --profile prod up -d

# Verifikasi
sleep 15
docker compose -f docker-compose.prod.yml -p rejki-prod ps
curl -sf http://localhost:8082/health

# Cek log
docker compose -f docker-compose.prod.yml -p rejki-prod logs --tail 20

Migrate Database (Prod)

cd /opt/rejki/prod/rejki-backend
bash scripts/migrate.sh prod
✅
Production Security Features

Rate limiting (3 zona), structured JSON logging, security headers (CSP, HSTS, Permissions-Policy), custom error pages (429, 502), ClamAV virus scan untuk upload dokumen, server_tokens off.

🔁 CI Workflow (ci.yml)

Selain deploy, setiap push dan PR ke develop/main juga menjalankan pipeline CI untuk memvalidasi kualitas kode sebelum di-merge:

Integration test tidak di CI

Integration test yang butuh PostgreSQL dijalankan manual saat development dan staging — tidak di CI untuk mempercepat pipeline (~5-10 menit lebih cepat). Coverage juga lib-only (tanpa DB) sehingga lebih cepat.

💾Backup Strategy

Backup dijadwalkan staggered agar tidak membebani PostgreSQL di waktu yang sama.

EnvironmentSchedule (Cron)Waktu (WIB)Destination
Production0 3 * * *03:00MinIO bucket rejki-backups
Development0 4 * * *04:00MinIO bucket rejki-backups

Backup Container (Prod Only)

Container db-backup di docker-compose.prod.yml menggunakan Dockerfile.backup. Melakukan pg_dump setiap jam 3 pagi, upload ke MinIO.

# Verifikasi backup berhasil
docker exec rejki-db-backup ls -la /backups

# Cek MinIO
docker exec rejki-minio mc ls local/rejki-backups/

# Restore jika diperlukan
docker exec -i rejki-postgres psql -U rejki -d rejki_prod < backup_file.sql
⚠️
Backup Testing

Lakukan test restore secara berkala (bulanan) untuk memastikan backup dapat digunakan. Simpan juga backup off-site (contoh: cron copy dari MinIO ke Google Drive atau S3 gratis).

Redis❌✅ redis_exporter✅ Alloyredis_exporter → Collector
Docker / Container❌✅ cAdvisor✅ AlloycAdvisor → Collector
VPS (OS level)❌✅ Node Exporter❌Node Exporter → Collector
✅
Grafana Cloud free tier — semuanya tercover!

Limit: 10k series metrics, 50GB logs, 50GB traces. Estimasi pemakaian kita: ~1.5k series, ~2-5GB logs/bulan, traces bisa diabaikan. Tidak ada trade-off signifikan — cuma butuh ~150MB RAM tambahan untuk exporter.

Catatan Penting

1. Observability stack jalan sebagai compose project terpisah (rejki-obs) — tidak perlu restart dev/prod.
2. Rust app dev & prod otomatis kirim traces ke rejki-otel-collector:4317 (via internal network rejki-infra).
3. Cukup aktifkan OTEL headers di dev/prod .env: OTEL_EXPORTER_OTLP_HEADERS=Authorization=Basic {base64}
4. Log shipping via Alloy otomatis — semua container stdout terkumpul ke Loki.
5. Node Exporter & cAdvisor perlu akses ke host filesystem (--volume /:/host) — itu normal.

🔒Security & Permission

🛡️ Ringkasan Keamanan

LapisanKonfigurasi
FirewallHanya port SSH (22) yang terbuka. Semua port aplikasi bind ke 127.0.0.1.
IngressCloudflare Tunnel — zero-trust, koneksi outbound dari VPS. Tidak ada port 80/443 terbuka.
DatabasePostgreSQL hanya listen di 127.0.0.1:5432. Authentication via password.
RedisRedis hanya listen di 127.0.0.1:6379. Tanpa auth (hanya internal).
MinIOMinIO hanya listen di 127.0.0.1:9000. Access key + secret key.
File PermissionDirektori /opt/rejki dimiliki user rejki:rejki. Kunci privat 600.
SSHHanya key-based authentication. Password login disabled.
JWTRS256 (asymmetric). Private key hanya di VPS. Public key di container.
EncryptionAES-256-GCM untuk data sensitif (phone, rekening). Key di .env.
Rate Limiting3 zona: umum (10r/s), auth (3r/s), strict (1r/s). Custom 429 response.
Virus ScanClamAV di production untuk semua upload dokumen.

🔧Troubleshooting

🔄

Container restart loop

Cek log: docker logs [container-name] --tail 50. Biasanya karena environment variable tidak terisi atau database belum siap.

LogEnv
🔌

Cannot connect to database

Pastikan container rejki-postgres ada di network yang sama: docker network inspect rejki-infra. Cek juga POSTGRES_PASSWORD di .env.

NetworkDatabase
🌐

Cloudflare Tunnel error

Cek docker logs rejki-tunnel. Pastikan TUNNEL_TOKEN valid. Cek juga DNS record di Cloudflare Dashboard.

TunnelDNS
💥

Out of memory (OOM)

VPS 2GB — matikan dev jika prod sedang sibuk. Cek docker stats untuk melihat memory usage realtime. Jika perlu, kurangi memory limit ClamAV.

MemoryOOM
🔑

GitHub Actions SSH failed

Verifikasi: (1) Public key ada di authorized_keys, (2) Permission file 600, (3) User rejki punya home /opt/rejki/.ssh, (4) Private key di GitHub Secrets format PEM.

SSHGitHub
🧪

Migration failed

Pastikan sqlx-cli terinstall: cargo install sqlx-cli. Cek juga DATABASE_URL sudah benar (dev → rejki_dev, prod → rejki_prod).

MigrationSQL
