📦 Rejki — Deployment Guide

Panduan step-by-step untuk mendeploy Rejki Backend (Rust) + Rejki Web (Vue 3) ke VPS.
Images di-push ke GitHub Container Registry (GHCR) — server hanya pull & restart.

ghcr.io docker compose cloudflare tunnel postgres redis

🏗️ Arsitektur Deployment

Berikut alur deploy dari push ke GitHub hingga running di VPS:

💡
Kenapa pakai GHCR? Kenapa tidak clone repo di server?

Tidak clone repo di server — lebih aman, tidak ada source code di VPS.
Tidak build di server — server tidak perlu Rust toolchain (hemat 1-2GB).
Deploy lebih cepat — pull image jauh lebih cepat daripada build dari source.
Reproducible — image yang di-push sudah terverifikasi oleh CI.

📁 Struktur File di Server

Ini adalah SATU-SATUNYA yang perlu ada di VPS — tidak perlu clone repo:

/opt/rejki/
│
├── infra/                    # Infrastructure — shared oleh dev & prod
│   ├── .env                   # POSTGRES_PASSWORD, MINIO keys, dll
│   └── docker-compose.yml     # postgres, redis, minio, clamav
│
├── dev/                      # Development environment
│   ├── .env                   # Env spesifik dev (APP_ENV=development, DB=rejki_dev)
│   ├── docker-compose.yml     # image: dari GHCR (tag: develop)
│   └── nginx.conf             # Nginx config untuk dev
│
├── prod/                     # Production environment
│   ├── .env                   # Env spesifik prod (APP_ENV=production, DB=rejki_prod)
│   ├── docker-compose.yml     # image: dari GHCR (tag: main)
│   └── nginx.conf             # Nginx config untuk prod
│
├── keys/                     # Sensitive keys — mount read-only ke container
│   ├── private.pem            # JWT private key (RS256)
│   ├── public.pem             # JWT public key
│   ├── firebase-service-account-dev.json
│   └── firebase-service-account-prod.json
│
└── scripts/                  # Helper scripts (opsional)
    └── deploy.sh              # One-touch deploy script
⚠️
PENTING: File .env TIDAK boleh di-commit ke git

File .env di setiap environment dibuat manual dan diisi dengan nilai yang sesuai. Gunakan .env.example dari repo sebagai template.

2 Setup GitHub Secrets

Buat GitHub Secrets di Settings → Secrets and variables → Actions untuk SETIAP repo:

Secret NameDeskripsiContoh Nilai
VPS_HOSTIP publik VPS103.xx.xx.xx
VPS_USERUsername SSHroot atau ubuntu
VPS_SSH_KEYPrivate key SSH-----BEGIN OPENSSH PRIVATE KEY-----...
VPS_PORTPort SSH22
GHCR_TOKENGitHub PAT untuk pull image(ganti dengan PAT Anda)

Cara buat GHCR_TOKEN:

  1. GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)
  2. Buat token baru dengan scope: read:packages, write:packages, delete:packages
  3. Copy token dan simpan sebagai secret GHCR_TOKEN di repo
⚠️
Repositori mana yang perlu secrets?

Kedua repo: rejki-backend dan rejki-web-dashboard. Secrets-nya SAMA (VPS yang sama).

3 Setup GitHub Container Registry

GitHub Container Registry (GHCR) adalah tempat penyimpanan Docker images. Ini otomatis aktif untuk akun GitHub.

3.1 Aktifkan GHCR untuk repo

  1. Buka repo di GitHub → Settings → Actions → General → Workflow permissions
  2. Pilih: Read and write permissions
  3. Centang: Allow GitHub Actions to create and approve pull requests

3.2 Verifikasi image sudah terpush

Setelah CI pertama jalan, image akan muncul di:
https://github.com/orgs/rejki/packages atau sidebar repo → Packages.

3.3 Image yang akan dibuat:

ghcr.io/rizkirchm97/rejki-backend:main          # Backend production
ghcr.io/rizkirchm97/rejki-backend:develop        # Backend development
ghcr.io/rizkirchm97/rejki-backend-notification:main   # Bun notification prod
ghcr.io/rizkirchm97/rejki-backend-notification:develop # Bun notification dev
ghcr.io/rizkirchm97/rejki-web:main               # Web production
ghcr.io/rizkirchm97/rejki-web:develop             # Web development

4 Setup SSH Key untuk GitHub Actions

GitHub Actions perlu akses SSH ke VPS untuk menjalankan perintah deploy.

4.1 Generate SSH key pair (di VPS atau lokal)

ssh-keygen -t ed25519 -C "github-actions-deploy" -f ~/.ssh/github-actions
# Ini menghasilkan 2 file:
#   ~/.ssh/github-actions      (private key)
#   ~/.ssh/github-actions.pub  (public key)

4.2 Tambahkan public key ke VPS

# Di VPS:
cat ~/.ssh/github-actions.pub >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys

4.3 Tambahkan private key ke GitHub Secrets

  1. Copy isi file private key: cat ~/.ssh/github-actions
  2. Buka repo → Settings → Secrets and variables → Actions
  3. Buat secret baru: VPS_SSH_KEY → paste private key
⚠️
Format private key harus tepat

Pastikan private key diawali dengan -----BEGIN OPENSSH PRIVATE KEY----- dan diakhiri -----END OPENSSH PRIVATE KEY-----. Jangan ada spasi ekstra.

5 Deploy Infrastructure

Infrastructure (PostgreSQL, Redis, MinIO, ClamAV) adalah shared component yang digunakan oleh dev dan prod.

💡
Infrastructure cukup di-deploy SEKALI

PostgreSQL, Redis, dan MinIO di-deploy sekali di awal. Tidak perlu di-deploy ulang setiap update backend.

5.1 Buat direktori infrastructure

sudo mkdir -p /opt/rejki/{infra,dev,prod,keys,scripts}
sudo chown -R $USER:$USER /opt/rejki

5.2 Copy file docker-compose infrastructure

File docker-compose.yml (infra only) ada di repo backend. Copy ke server:

# Dari lokal, SCP file infra ke server:
scp docker-compose.yml user@vps:/opt/rejki/infra/docker-compose.yml

# Atau buat manual di server:
nano /opt/rejki/infra/docker-compose.yml
# Paste dari isi docker-compose.yml (base — postgres, redis, minio, clamav)

5.3 Buat file .env infrastructure

nano /opt/rejki/infra/.env

Isi dengan:

POSTGRES_PASSWORD=<password-kuat-random>
MINIO_ACCESS_KEY=rejkiadmin
MINIO_SECRET_KEY=<password-kuat-random>

5.4 Setup JWT keys

# Generate RS256 key pair (jika belum punya)
openssl genpkey -algorithm RSA -out /opt/rejki/keys/private.pem -pkeyopt rsa_keygen_bits:2048
openssl rsa -pubout -in /opt/rejki/keys/private.pem -out /opt/rejki/keys/public.pem
chmod 600 /opt/rejki/keys/*.pem

5.5 Start infrastructure

cd /opt/rejki/infra
docker compose --env-file .env up -d

# Verifikasi semua service running
docker compose ps

# Test PostgreSQL
docker compose exec postgres pg_isready -U rejki

# Test Redis
docker compose exec redis redis-cli ping
✅
Verifikasi Step 5

docker compose ps → postgres, redis, minio, clamav semuanya Up.

6 Deploy Backend (Dev & Prod)

6.1 Buat file docker-compose untuk backend

File docker-compose.dev.yml dan docker-compose.prod.yml otomatis di-copy oleh GitHub Actions via SCP ke VPS.

Atau bisa dibuat manual di server:

Dev:

nano /opt/rejki/dev/docker-compose.yml
# Isi: copy dari docker-compose.dev.yml di repo (sudah tanpa build block)

Prod:

nano /opt/rejki/prod/docker-compose.yml
# Isi: copy dari docker-compose.prod.yml di repo (sudah tanpa build block)

6.2 Buat file .env untuk masing-masing environment

Template ada di repo: .env.example, .env.dev.example, .env.prod.example

# Dev
nano /opt/rejki/dev/.env
# Isi minimal:
APP_ENV=development
POSTGRES_PASSWORD=<sama-dengan-infra>
RUST_LOG=debug
CORS_ALLOWED_ORIGINS=http://dev.rejki.id
TUNNEL_TOKEN=<cloudflare-tunnel-token>

# Prod
nano /opt/rejki/prod/.env
# Isi minimal:
APP_ENV=production
POSTGRES_PASSWORD=<sama-dengan-infra>
RUST_LOG=warn
CORS_ALLOWED_ORIGINS=https://rejki.id,https://app.rejki.id
TUNNEL_TOKEN=<cloudflare-tunnel-token>
DATA_ENCRYPTION_KEY=<base64-key>  # generate: openssl rand -base64 32

6.3 Deploy via GitHub Actions

Cukup push ke branch yang sesuai. Deploy otomatis berjalan:

# Deploy dev
git push origin develop
# → CI Build → Push image → SSH deploy-dev.yml

# Deploy prod
git push origin main
# → CI Build → Push image → SSH deploy.yml

6.4 Database Migration

Migrasi dijalankan OTOMATIS oleh deploy workflow setelah service up. Jika ingin manual:

# Dev
docker compose -f /opt/rejki/dev/docker-compose.yml --env-file /opt/rejki/dev/.env exec -T rejki-app /app/rejki-app migrate

# Prod
docker compose -f /opt/rejki/prod/docker-compose.yml --env-file /opt/rejki/prod/.env exec -T rejki-app /app/rejki-app migrate

7 Deploy Web Frontend

Sama seperti backend — cukup push ke branch:

# Deploy dev
cd rejki-web-dashboard
git push origin develop
# → CI Build image → Push ke GHCR → SSH deploy-dev.yml

# Deploy prod
git push origin main
# → CI Build image → Push ke GHCR → SSH deploy.yml

Web deploy workflow hanya melakukan:

  1. docker login ghcr.io
  2. docker compose pull rejki-web
  3. docker compose up -d rejki-web

File docker-compose.yml yang digunakan web ada di folder /opt/rejki/dev/ dan /opt/rejki/prod/ — DIKELOLA oleh repo backend (service rejki-web sudah termasuk di dalamnya).

⚠️
PENTING: docker-compose web ada di backend repo

Service rejki-web didefinisikan di docker-compose.dev.yml dan docker-compose.prod.yml milik backend. Jadi update compose file harus dari backend repo.

8 Setup Cloudflare Tunnel

Cloudflare Tunnel menyediakan akses HTTPS tanpa perlu membuka port di firewall.

8.1 Setup Tunnel di Cloudflare Dashboard

  1. Login ke Cloudflare Dashboard → Zero Trust → Networks → Tunnels
  2. Buat tunnel baru (nama: rejki-tunnel)
  3. Pilih: Docker → akan muncul perintah docker run cloudflare/cloudflared ...
  4. Catat Tunnel Token — ini yang akan dimasukkan ke .env

8.2 Setup DNS

Di Cloudflare Dashboard → DNS → Records, tambahkan:

TypeNameTarget
CNAMEdevdev.rejki.id → tunnel
CNAME@rejki.id → tunnel
CNAMEappapp.rejki.id → tunnel

8.3 Konfigurasi Tunnel di Cloudflare Zero Trust

Di halaman Tunnel → Edit → Public Hostname:

HostnameService
dev.rejki.idhttp://localhost:8081 (nginx dev)
rejki.idhttp://localhost:8082 (nginx prod)
app.rejki.idhttp://localhost:8082 (nginx prod)
💡
Cloudflare Tunnel vs port forwarding

Dengan tunnel, VPS tidak perlu membuka port 80/443 di firewall. Semua traffic masuk via tunnel Cloudflare. Lebih aman.

9 Verifikasi

Setelah semua service running, lakukan verifikasi berikut:

9.1 Cek container status

# Infra
docker compose -f /opt/rejki/infra/docker-compose.yml ps

# Dev
docker compose -f /opt/rejki/dev/docker-compose.yml ps

# Prod
docker compose -f /opt/rejki/prod/docker-compose.yml ps

9.2 Cek health endpoint

# Dev
curl -sf http://localhost:8081/health

# Prod
curl -sf http://localhost:8082/health

Response yang diharapkan: {"status":"ok"} atau response JSON dengan HTTP 200.

9.3 Cek log

# Backend
docker logs --tail 50 rejki-app-dev
docker logs --tail 50 rejki-app-prod

# Web
docker logs --tail 50 rejki-web-dev
docker logs --tail 50 rejki-web-prod

# Nginx
docker logs --tail 50 rejki-nginx-dev
docker logs --tail 50 rejki-nginx-prod

9.4 Checklist Verifikasi

  • PostgreSQL running dan bisa diakses
  • Redis running dan merespon ping
  • MinIO running dan console bisa diakses
  • Backend app merespon di /health (port 8081/8082)
  • Web frontend bisa diakses via browser
  • Cloudflare tunnel active (Zero Trust dashboard)
  • Domain bisa diakses via HTTPS
  • CORS berfungsi (frontend bisa panggil API)

10 Rollback

Jika deploy gagal atau menyebabkan masalah, lakukan rollback:

10.1 Rollback Backend

# 1. Lihat image tag yang tersedia
docker images ghcr.io/rizkirchm97/rejki-backend

# 2. Pull image versi sebelumnya
docker pull ghcr.io/rizkirchm97/rejki-backend:develop-abc1234

# 3. Tag ulang ke develop
docker tag ghcr.io/rizkirchm97/rejki-backend:develop-abc1234 \
  ghcr.io/rizkirchm97/rejki-backend:develop

# 4. Restart
docker compose -f /opt/rejki/dev/docker-compose.yml up -d rejki-app

10.2 Rollback Web

# Pull image versi sebelumnya
docker pull ghcr.io/rizkirchm97/rejki-web:develop-abc1234
docker tag ghcr.io/rizkirchm97/rejki-web:develop-abc1234 \
  ghcr.io/rizkirchm97/rejki-web:develop
docker compose -f /opt/rejki/dev/docker-compose.yml up -d rejki-web

10.3 Rollback via Git

Jika perlu rollback ke commit tertentu dan trigger deploy ulang:

git revert <commit-hash>
git push origin develop
# CI akan build image baru dari hasil revert, lalu deploy
