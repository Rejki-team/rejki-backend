Phase 1.5 — Logging Standard

Logging & Observability

Standar format log, level penggunaan, field wajib, dan apa yang tidak boleh di-log di seluruh service Rejki Backend. Log yang konsisten adalah fondasi debugging production.

Phase 1.5 JSON Structured tracing crate

🧭Prinsip

Structured, bukan plaintextSemua log dalam format JSON agar bisa di-query, di-filter, dan di-aggregate oleh log aggregator (Loki, Elasticsearch, Cloudwatch).
Setiap log punya request_idSemua log dalam satu request dapat ditelusuri dari satu ID. Tanpa ini, debugging multi-service tidak mungkin.
Log untuk mesin, bukan manusiaJangan tulis prose panjang di log message. Tulis event singkat, letakkan data di field terstruktur.
Level bermaknaGunakan level yang tepat. INFO yang terlalu banyak sama buruknya dengan tidak ada log — noise menutupi sinyal.
Tidak ada data sensitifPassword, token, OTP, NIK tidak pernah masuk log — bahkan di level DEBUG.

📊Log Level

LevelKapan DigunakanContoh
ERROROperasi gagal dan tidak bisa di-recover. Perlu investigasi segera. Selalu alert production.DB connection gagal, panic, external service down
WARNKondisi tidak normal tapi operasi masih bisa lanjut. Perlu dimonitor tapi tidak urgent.Retry attempt, token hampir expired, queue backlog tinggi
INFOEvent penting di alur normal. Harus informatif tanpa verbose. Dipakai di production.Server start, request masuk (summary), user login, resource dibuat
DEBUGDetail untuk debugging. Dimatikan di production. Aktif hanya saat investigasi.Query SQL hasil, payload request, state internal service
TRACESangat verbose — setiap langkah kecil. Hanya lokal, tidak pernah di staging/production.Loop iteration, byte-level data, function call chain
⚠️
Level default per environment

Development: DEBUG · Staging: INFO · Production: INFO (bisa switch ke DEBUG sementara via env var tanpa restart). Set via RUST_LOG=rejki=info,sqlx=warn.

📋Format JSON

Setiap baris log adalah satu JSON object. Tidak ada multi-line log — jika ada newline dalam message, escape menjadi \n.

Format Standar
{
  "timestamp": "2026-06-09T10:00:00.123Z",   // ISO 8601 UTC, presisi millisecond
  "level":     "INFO",                        // TRACE | DEBUG | INFO | WARN | ERROR
  "target":    "auth_service::interface",      // Rust module path
  "message":   "user login success",           // singkat, lowercase, past tense
  "request_id":"req_7f3a9c2d",               // wajib di semua log dalam request
  "user_id":   "550e8400-uuid",              // jika ada konteks user
  "duration_ms": 42,                        // durasi operasi dalam ms
  "service":   "auth-service",               // nama service
  "env":       "production"                   // dari ENV env var
}
Format Error Log
{
  "timestamp": "2026-06-09T10:00:01.456Z",
  "level":     "ERROR",
  "target":    "auth_service::infrastructure",
  "message":   "database query failed",
  "request_id":"req_7f3a9c2d",
  "error":     "connection pool timeout after 30s",  // detail error — TIDAK dikirim ke client
  "service":   "auth-service",
  "env":       "production"
}

📌Field Wajib

FieldTipeWajib?Keterangan
timestampstring ISO 8601SelaluUTC, presisi millisecond. tracing-subscriber generate otomatis.
levelstringSelaluUPPERCASE: TRACE / DEBUG / INFO / WARN / ERROR.
targetstringSelaluRust module path — otomatis dari tracing. Berguna untuk filter per modul.
messagestringSelaluSingkat, lowercase, past tense. Maks 80 karakter. Data detail ada di field lain.
servicestringSelaluNama service: auth-service, user-service, dll. Set saat init tracing.
envstringSelaluDari env var ENV: development / staging / production.
request_idstringDalam requestPropagasi dari HTTP header X-Request-ID via tracing span.
user_idstring UUIDJika authAda saat request sudah melewati auth middleware. Jangan log jika belum auth.
duration_msnumberAkhir operasiDurasi operasi dalam millisecond. Wajib di log request selesai dan DB query.
errorstringSaat ERROR/WARNPesan error internal. Tidak pernah dikirim ke client — hanya ada di log.

🏗️Konteks Log per Layer

Interface Layer — HTTP Request/Response
// Log di awal setiap request (via TraceLayer)
{ "level": "INFO", "message": "request started",
  "method": "POST", "path": "/api/v1/auth/login",
  "request_id": "req_...", "ip": "1.2.3.4" }

// Log di akhir request
{ "level": "INFO", "message": "request completed",
  "method": "POST", "path": "/api/v1/auth/login",
  "status": 200, "duration_ms": 42, "request_id": "req_..." }

// Log auth failure — WARN bukan ERROR (ini kondisi normal)
{ "level": "WARN", "message": "login failed",
  "reason": "invalid credentials", "email_hash": "sha256(email)",
  "request_id": "req_..." }  // email di-hash, bukan plaintext
Application Layer — Business Events
// Event bisnis penting — INFO
{ "level": "INFO", "message": "user registered",
  "user_id": "uuid", "request_id": "req_..." }

{ "level": "INFO", "message": "iklan created",
  "iklan_id": "uuid", "user_id": "uuid",
  "type": "pekerjaan", "request_id": "req_..." }

// Validasi bisnis gagal — WARN (bukan ERROR, ini expected)
{ "level": "WARN", "message": "otp expired",
  "user_id": "uuid", "request_id": "req_..." }
Infrastructure Layer — DB & External
// Query lambat — WARN jika > 100ms
{ "level": "WARN", "message": "slow query",
  "duration_ms": 230, "query": "SELECT ... FROM auth.users",
  "request_id": "req_..." }  // query tanpa parameter value

// DB error — ERROR
{ "level": "ERROR", "message": "database error",
  "error": "unique violation on auth.users.email",
  "request_id": "req_..." }

// Startup — INFO
{ "level": "INFO", "message": "database connected",
  "pool_size": 10, "service": "auth-service" }

🚫Yang Tidak Boleh Di-log

DataAlasanGantinya
Password (plaintext atau hash)Bocor via log aggregatorJangan log sama sekali
Access token / refresh tokenToken bisa langsung dipakai untuk impersonasiLog hanya token_prefix (8 char pertama)
OTPOTP bisa langsung dipakaiLog hanya otp_sent: true
Email plaintext di WARN/ERRORPII — bisa jadi masalah GDPR/PDPLog SHA-256 hash email untuk korelasi
NIK / no. HP / rekening bankData sensitif regulasi PDP IndonesiaLog hanya user_id
SQL query dengan parameter valueData user muncul di logLog query template saja (tanpa $1 value)
Request body lengkapBerisi password, data pribadiLog hanya field non-sensitif yang relevan
Stack trace ke log INFONoise — stack trace hanya di ERRORLog message + error field saja

🔗Distributed Tracing via request_id

Semua log dalam satu request harus membawa request_id yang sama, sehingga bisa di-trace dari awal hingga akhir — bahkan lintas service (in-process).

// rejki-app/src/main.rs — middleware inject request_id ke tracing span
// Setiap request otomatis punya span dengan request_id

// Contoh trace satu login request:
// request_id: req_abc123

{ "msg": "request started",    "request_id": "req_abc123", "path": "/api/v1/auth/login" }
{ "msg": "db query started",    "request_id": "req_abc123", "table": "auth.users" }
{ "msg": "db query completed",  "request_id": "req_abc123", "duration_ms": 12 }
{ "msg": "token issued",        "request_id": "req_abc123", "user_id": "uuid" }
{ "msg": "request completed",   "request_id": "req_abc123", "status": 200, "duration_ms": 42 }

// Filter semua log untuk satu request:
// jq 'select(.request_id == "req_abc123")' app.log

⚙️Implementasi Rust

common/tracing-setup — update untuk JSON output
// common/tracing-setup/src/lib.rs
pub fn init_tracing() {
  let env = std::env::var("ENV").unwrap_or_else(|_| "development".into());
  let service = std::env::var("SERVICE_NAME").unwrap_or_else(|_| "rejki".into());

  if env == "production" || env == "staging" {
    // JSON structured untuk production — bisa di-ingest log aggregator
    tracing_subscriber::fmt()
      .json()
      .with_current_span(true)
      .with_span_list(true)
      .with_env_filter(EnvFilter::from_default_env())
      .init();
  } else {
    // Pretty format untuk development — mudah dibaca manusia
    tracing_subscriber::fmt()
      .pretty()
      .with_env_filter(EnvFilter::from_default_env())
      .init();
  }
}
Penggunaan di Handler
// Di handler — gunakan tracing macro, bukan println!
tracing::info!(
  user_id = %claims.sub,
  request_id = %req_id,
  "user login success"
);

tracing::warn!(
  request_id = %req_id,
  reason = "invalid credentials",
  "login failed"
);

tracing::error!(
  request_id = %req_id,
  error = %err,  // detail error hanya di log, tidak ke client
  "database query failed"
);
