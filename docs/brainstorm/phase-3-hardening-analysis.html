⚠️Katalog Gap — 22 Kebutuhan Nyata

A. 🔐 Security Hardening (6 gap)

A1 Rate limiting endpoint bisnis P0

Hanya auth-service yang punya rate limiter (Redis Lua atomik). 4 iklan, user, chat, report, corporate-comms — tidak ada proteksi DoS/brute-force sama sekali.

Evidence: OtpRateLimiter di auth-service/infrastructure/rate_limit.rs. Tidak ada tower-governor di Cargo.toml manapun. Tidak ada RateLimiter trait di service lain.

A2 Multi-tier RBAC ✅ DONE

✅ W3B-05 selesai 19 Jun 2026. 6 role hierarchy (SuperAdmin 100, AdminIklan/AdminUser 80, Moderator 60, UserVerified 40, User 20) + require_role(min_rank) middleware ganti require_admin + AppError::InsufficientRole (403 INSUFFICIENT_ROLE) + migration alter CHECK constraint + 8 router update + admin_login guard >= 80. tasks.md

Evidence: auth-service-client/src/lib.rs — 6 variant Role + rank(). common/auth-middleware/src/lib.rs — require_role(min_rank: u8). 8 service interface/mod.rs — from_fn(require_admin) → from_fn_with_state(rank, require_role). auth-service/application/service.rs — admin_login guard rank() >= 80.

A3 audit_log table ✅ DONE

✅ W3B-04 selesai 19 Jun 2026. Migration auth.audit_log (append-only), PgAuditLogRepository, 11 AuditEvent variant, inject ke 10 auth events (login, admin_login, logout, refresh, OTP sent, password changed/reset, suspend/bulk), AuditContext FromRequestParts extractor, fail-open. tasks.md

Evidence: 67 auth unit tests PASS, 247 total + 50 integration PASS. Migration applied to dev & test DB.

A4 CORS production policy ✅ W3C-08 selesai 20 Jun 2026

✅ CORS_ALLOWED_ORIGINS env var (default: rejki.id,app.rejki.id). Conditional CorsLayer: development=Any, production=whitelist + allow_credentials(true). Methods terbatas: GET/POST/PATCH/DELETE/OPTIONS. Fail-fast parsing di AppConfig startup.

Implementation: common/config/src/lib.rs + rejki-app/src/main.rs — CorsLayer conditional is_production().

A5 Enkripsi at rest (phone, rekening) ✅ W3C-09 selesai 20 Jun 2026

✅ AES-256-GCM via common-crypto. Phone di auth-service sekarang didekripsi di repository layer. User-service: kolom baru phone_encrypted + rekening_encrypted (JSON: bank, number, holder). Decrypt transparan di repo, masking di response (****1234). Key rotation strategy didokumentasikan di security-baseline.

Evidence: common/crypto/src/lib.rs — encrypt/decrypt AES-256-GCM. auth-service/pg_repository.rs — row_to_user decrypt phone. user-service: encrypt di INSERT/UPDATE, decrypt di SELECT. Rekening sebagai JSON terenkripsi + parsial masking.

A6 Dependency audit (cargo audit/deny) ✅ W3D-13 selesai 22 Jun 2026

✅ Dua job baru di CI pipeline (schedule mingguan, bukan setiap PR): cargo-audit — CVE scan fail on CRITICAL/HIGH via cargo audit --deny warnings. cargo-deny — license compliance reject GPL/AGPL via cargo deny check licenses. Konfigurasi di rust-services/deny.toml.

Evidence: .github/workflows/ci.yml — +schedule cron 0 6 * * 1, +cargo-audit job, +cargo-deny job. rust-services/deny.toml — license allow/deny list + advisory config.

C. 🏗️ Data Integrity & Schema (3 gap)

C1 region_id FK di 4 iklan entities P0

Semua 4 entity pakai lokasi: Option<String> free-text. Region service sudah menyediakan reference data 4-level (province→kabupaten→kecamatan→kelurahan) tapi tidak digunakan. Ini memblokir analytics geografis dan pencarian berbasis lokasi yang akurat.

Evidence: IklanPekerjaan.lokasi: Option<String>, IklanPekerja.lokasi: Option<String>, IklanBarangBekas.lokasi: Option<String>, IklanPelatihan.lokasi: Option<String>. Tidak ada region_id di entity manapun.

C2 Validasi region_id di user profiles P2

user_svc.profiles sudah punya province_id, regency_id, district_id, village_id. Tapi validasi referensial masih di application layer. Bisa diperkuat dengan trigger/check constraint atau validasi chain (parent_id consistency).

Evidence: user-service/src/application/service.rs — validasi region dilakukan manual di service layer, bukan DB constraint.

C3 Scheduled hard-delete expired data P3

Soft delete sudah diterapkan di semua entity (deleted_at). Tapi tidak ada scheduled job untuk hard-delete data > N hari (PDP compliance — retensi).

Evidence: Semua query sudah AND deleted_at IS NULL. Tidak ada scheduled task/job untuk purge data lama.

D. 🔄 Fitur yang Masih Kurang (5 gap)

D1 PATCH iklan (update) ✅ W3B-06 selesai 19 Jun 2026

✅ 4 iklan service (pekerjaan, pekerja, barang-bekas, pelatihan) sudah punya PATCH /{id} handler. Partial update via COALESCE SQL. Lifecycle guard per service. is_active toggle. IDOR 404. Rate limited. Swagger DTO mirror di rejki-app.

Implementation: iklan-*-service/src/{application/dto.rs, domain/repository.rs, infrastructure/pg_repository.rs, application/service.rs, interface/handlers.rs, interface/mod.rs} — semua punya update() method.

D2 Password reset flow ✅ W3B-07 selesai 19 Jun 2026

✅ Forgot-password + reset-password + change-password (OTP-based). Anti-enumeration, rate limit 3 req/15m, atomik transaction consume OTP + update password + revoke tokens, audit event via W3B-04. Semua endpoint sudah terimplementasi sejak change extend-auth-service-onboarding.

Implementation: auth-service/src/{domain/entity.rs, application/dto.rs, application/service.rs, infrastructure/pg_repository.rs, interface/handlers.rs, interface/mod.rs} — OtpPurpose::ResetPassword, forgot_password(), reset_password(), change_password(), consume_otp_and_update_password_transactional().

D3 Device token management P2

FCM push notification sudah berfungsi (Redis Streams → Bun consumer). Tapi endpoint register/unregister device token (POST/DELETE /notif/device-tokens) perlu diverifikasi — mungkin partial.

Evidence: Perlu verifikasi kode di notification-service/interface/handlers.rs untuk endpoint device-token.

D4 Idempotency-Key implementation P3

API standard mendokumentasikan header Idempotency-Key untuk POST kritis. Tidak ada tabel idempotency_keys atau logic handler. Saat ini hanya uniqueness constraint DB yang mencegah double submit (partial protection).

Evidence: api-standard.html §Idempotency menyebut Idempotency-Key header. Search graph 0 results untuk idempotency. Tidak ada tabel idempotency_keys.

D5 argon2 password hashing P3

Saat ini bcrypt (cost 12). Security baseline menyebut argon2 sebagai upgrade opsional Phase 3. Bukan prioritas — bcrypt sudah cukup aman untuk skala saat ini.

Evidence: security-baseline.html §Password Hashing: "Dengan argon2 sebagai upgrade opsional di Phase 3."
