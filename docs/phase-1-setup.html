AppError — JSON response body (standar industri)

Semua error response mengembalikan JSON dengan field error (kode mesin) dan message (pesan human-readable). Bukan plain text.

rustcommon/errors/src/lib.rs
use axum::response::{IntoResponse, Json, Response};
use serde::Serialize;

#[derive(Serialize)]
struct ErrorBody {
    error:   &'static str,   // kode mesin: "NOT_FOUND", "VALIDATION_ERROR", dll.
    message: String,         // pesan human-readable
}

impl IntoResponse for AppError {
    fn into_response(self) -> Response {
        let (status, code, message) = match self {
            AppError::NotFound(m)   => (StatusCode::NOT_FOUND,             "NOT_FOUND",        m),
            AppError::Unauthorized  => (StatusCode::UNAUTHORIZED,          "UNAUTHORIZED",     "unauthorized".into()),
            AppError::Validation(m) => (StatusCode::UNPROCESSABLE_ENTITY, "VALIDATION_ERROR", m),
            AppError::Conflict(m)   => (StatusCode::CONFLICT,             "CONFLICT",         m),
            AppError::Forbidden(m)  => (StatusCode::FORBIDDEN,             "FORBIDDEN",        m),
            AppError::Internal(e)   => {
                tracing::error!(error = ?e, "internal server error");
                (StatusCode::INTERNAL_SERVER_ERROR, "INTERNAL_ERROR", "internal server error".into())
            }
        };
        (status, Json(ErrorBody { error: code, message })).into_response()
    }
}

Response format

Client mobile/web selalu bisa JSON.parse response body tanpa Content-Type check terlebih dahulu. Field error digunakan untuk switch-case di client, message untuk ditampilkan ke user.

auth-middleware — Dependency Inversion, bukan decode JWT sendiri

Middleware tidak boleh decode JWT secara langsung (butuh public key tersebar ke semua service). Middleware hanya memanggil AuthClient trait yang di-inject oleh rejki-app.

rustcommon/auth-middleware/src/lib.rs
// Cara pakai di router yang butuh auth:
// .layer(axum::middleware::from_fn_with_state(auth_client, require_auth))

pub async fn require_auth(
    State(auth): State<Arc<dyn AuthClient>>,
    mut req: Request,
    next: Next,
) -> Result<Response, AppError> {
    let token = extract_bearer(req.headers())
        .ok_or(AppError::Unauthorized)?;

    let claims = auth
        .validate_token(token).await
        .map_err(|_| AppError::Unauthorized)?;

    req.extensions_mut().insert(claims);
    Ok(next.run(req).await)
}
✅
Kenapa pola ini benar

Public key JWT hanya ada di auth-service. Middleware tidak decode — ia hanya delegasikan ke AuthClient trait. Saat service diekstrak, implementasi trait berubah dari in-process call menjadi HTTP call; middleware tidak perlu diubah.

infrastructure/pg_repository.rs — Implementasi dengan sqlx

rustauth-service/src/infrastructure/pg_repository.rs
pub struct PgAuthRepository { pool: PgPool }

impl AuthRepository for PgAuthRepository {
    async fn consume_otp(&self, user_id: Uuid, otp_hash: &str, purpose: &str)
        -> Result<bool, anyhow::Error>
    {
        let result = sqlx::query!(
            r#"DELETE FROM auth.otp_verifications
               WHERE user_id = $1 AND otp_hash = $2 AND purpose = $3
                 AND expires_at > now()"#,
            user_id, otp_hash, purpose
        ).execute(&self.pool).await?;
        Ok(result.rows_affected() > 0)
    }
}
💡
OTP consume atomik

DELETE + cek rows_affected dalam satu query. Tidak ada race condition — dua request yang datang bersamaan tidak bisa sama-sama consume OTP yang sama.

    Router::new()

        .route("/login",     post(handlers::login))

        .route("/logout",    post(handlers::logout))
        .with_state(state)
}

1

infrastructure/jwt.rs — JwtService (RS256)

rustauth-service/src/infrastructure/jwt.rs
use jsonwebtoken::{decode, encode, Algorithm, DecodingKey, EncodingKey, Header, Validation};

pub struct JwtService {
    encoding_key: EncodingKey,
    decoding_key: DecodingKey,
    access_ttl:   i64, // detik
}

impl JwtService {
    pub fn from_files(private_pem: &str, public_pem: &str, access_ttl_secs: i64)
        -> anyhow::Result<Self>
    {
        let encoding_key = EncodingKey::from_rsa_pem(private_pem.as_bytes())?;
        let decoding_key = DecodingKey::from_rsa_pem(public_pem.as_bytes())?;
        Ok(Self { encoding_key, decoding_key, access_ttl: access_ttl_secs })
    }

    pub fn issue_access_token(&self, user_id: Uuid, email: &str)
        -> anyhow::Result<String>
    {
        let now = Utc::now().timestamp();
        let claims = JwtClaims { sub: user_id.to_string(), email: email.into(),
                                   iat: now, exp: now + self.access_ttl };
        encode(&Header::new(Algorithm::RS256), &claims, &self.encoding_key)
            .map_err(|e| anyhow::anyhow!("gagal sign token: {e}"))
    }

    pub fn validate_token(&self, token: &str)
        -> Result<AuthClaims, AuthClientError>
    {
        let data = decode::<JwtClaims>(token, &self.decoding_key,
                       &Validation::new(Algorithm::RS256))
            .map_err(|_| AuthClientError::InvalidToken)?;
        let user_id = Uuid::parse_str(&data.claims.sub)
            .map_err(|_| AuthClientError::InvalidToken)?;
        Ok(AuthClaims { user_id, email: data.claims.email })
    }
}

application/service.rs — Login + Refresh + Logout lengkap

OTP di-hash dengan SHA-256. Refresh token di-hash sebelum disimpan di DB. Rotasi refresh token: token lama dihapus, token baru diissue dalam satu login cycle.

rustauth-service/src/application/service.rs
pub struct AuthService<R: AuthRepository> {
    repo:        Arc<R>,
    jwt:         Arc<JwtService>,
    refresh_ttl: i64,
}

impl<R: AuthRepository> AuthService<R> {
    pub async fn login(&self, input: LoginInput) -> Result<TokenPair, anyhow::Error> {
        let user = self.repo.find_by_email(&input.email).await?
            .ok_or_else(|| anyhow!("email atau password salah"))?;
        verify(&input.password, &user.password_hash)?;

        let access_token  = self.jwt.issue_access_token(user.id, &user.email)?;
        let refresh_token = generate_refresh_token(); // 32 bytes random hex
        let refresh_hash  = hash_token(&refresh_token); // SHA-256 sebelum simpan ke DB
        self.repo.save_refresh_token(user.id, &refresh_hash, expires_at).await?;

        Ok(TokenPair { access_token, refresh_token, token_type: "Bearer".into(), expires_in: 900 })
    }

    pub async fn refresh(&self, input: RefreshInput) -> Result<TokenPair, anyhow::Error> {
        let token_hash = hash_token(&input.refresh_token);
        let user_id    = self.repo.find_user_by_refresh_token(&token_hash).await?
            .ok_or_else(|| anyhow!("refresh token tidak valid"))?;
        self.repo.revoke_refresh_token(&token_hash).await?; // rotasi
        // ... issue access + refresh token baru
    }

    pub async fn logout(&self, refresh_token: &str) -> Result<(), anyhow::Error> {
        let token_hash = hash_token(refresh_token);
        self.repo.revoke_refresh_token(&token_hash).await
    }
}
💡
Token rotation

Setiap /refresh → token lama direvoke, token baru diissue. Jika refresh token bocor, penyerang hanya bisa pakai sekali — rotasi membatalkan session mereka di request berikutnya.

main.rs — Wire semua service + JwtService + CORS + Compression

rustrejki-app/src/main.rs
use std::sync::Arc;
use tower_http::{cors::{Any, CorsLayer}, trace::TraceLayer, compression::CompressionLayer};

#[tokio::main]
async fn main() {
    // APP_ENV wajib di-set: "development" | "production"
    let app_env = std::env::var("APP_ENV").expect("APP_ENV tidak di-set (development | production)");
    if app_env == "development" {
        dotenvy::dotenv().ok(); // .env hanya di-load saat development
    }
    common_tracing::init_tracing();

    let pool = sqlx::PgPool::connect(
        &std::env::var("DATABASE_URL").expect("DATABASE_URL tidak di-set")
    ).await.expect("gagal connect ke PostgreSQL");

    // JwtService — diinisiasi sekali, di-share via Arc
    let private_pem = std::fs::read_to_string(
        std::env::var("JWT_PRIVATE_KEY_PATH").unwrap_or_else(|_| "./keys/private.pem".into())
    ).expect("JWT_PRIVATE_KEY_PATH tidak ditemukan");
    let public_pem = std::fs::read_to_string(
        std::env::var("JWT_PUBLIC_KEY_PATH").unwrap_or_else(|_| "./keys/public.pem".into())
    ).expect("JWT_PUBLIC_KEY_PATH tidak ditemukan");
    let access_ttl: i64 = std::env::var("JWT_ACCESS_TTL_SECS")
        .ok().and_then(|v| v.parse().ok()).unwrap_or(900);
    let jwt = Arc::new(
        auth_service::JwtService::from_files(&private_pem, &public_pem, access_ttl)
            .expect("gagal inisiasi JwtService")
    );

    // AuthClient — in-process implementasi, di-inject ke middleware semua service
    let auth_client: Arc<dyn auth_service_client::AuthClient> =
        Arc::new(auth_service::AuthInProcessClient::new(jwt.clone()));

    let app = Router::new()
        .nest("/api/auth",      auth_service::router_with_jwt(pool.clone(), jwt.clone()))
        .nest("/api/users",     user_service::router(pool.clone()))
        .nest("/api/chat",      chat_service::router(pool.clone()))
        .nest("/api/notif",     notification_service::router(pool.clone()))
        .nest("/api/pekerjaan", iklan_pekerjaan_service::router(pool.clone()))
        .nest("/api/pekerja",   iklan_pekerja_service::router(pool.clone()))
        .nest("/api/barang",    iklan_barang_bekas_service::router(pool.clone()))
        .nest("/api/pelatihan", iklan_pelatihan_service::router(pool.clone()))
        .layer(CompressionLayer::new())
        .layer(TraceLayer::new_for_http())
        .layer(CorsLayer::new().allow_origin(Any).allow_methods(Any).allow_headers(Any));

    let port     = std::env::var("APP_PORT").unwrap_or_else(|_| "8080".into());
    let listener = tokio::net::TcpListener::bind(format!("0.0.0.0:{port}")).await.unwrap();
    tracing::info!(port = %port, "rejki-app listening");
    axum::serve(listener, app).await.unwrap();
}
✅
APP_ENV fail-fast — .env hanya di development

APP_ENV wajib di-set sebelum apapun berjalan — service langsung panic jika tidak ada. dotenvy::dotenv() hanya dipanggil jika APP_ENV=development; di production env var dibaca langsung dari system environment tanpa file .env.

💡
JwtService di-share, bukan dicopy

Arc<JwtService> dibuat sekali di Composition Root. auth_service::router_with_jwt menerimanya langsung — tidak perlu baca file PEM dua kali. Saat diekstrak, AuthInProcessClient diganti HttpAuthClient tanpa perubahan pada router service lain.
