Phase 1.5 — WebSocket Contract

WebSocket Contract

Standar format message, autentikasi koneksi, event naming, reconnect strategy, dan error handling untuk chat-service WebSocket Rejki Backend.

Phase 1.5 WebSocket chat-service

🧭Prinsip

Envelope sama dengan RESTFormat { type, payload, request_id } konsisten — client tidak perlu logika parsing berbeda untuk WS vs REST.
Auth di handshake, bukan per messageToken JWT divalidasi saat koneksi dibuat via query param atau header. Setelah terkoneksi, tidak perlu kirim token per pesan.
Event-driven, bukan pollingServer push event ke client saat ada update. Client tidak perlu polling — satu koneksi WS menggantikan ratusan HTTP request.
Reconnect otomatis di clientServer tidak menjamin koneksi persisten. Client wajib implementasi exponential backoff reconnect.
Stateless serverServer tidak menyimpan state koneksi di memory. Pesan di-persist ke DB, state di-recover dari DB saat reconnect.

🔐Autentikasi Koneksi

WebSocket tidak mendukung custom header di browser. Gunakan query parameter untuk kirim token saat handshake.

URL Koneksi
# Format koneksi WebSocket
wss://api.rejki.id/api/v1/chat/ws?token={access_token}&room={room_id}

# Contoh
wss://api.rejki.id/api/v1/chat/ws?token=eyJhbGci...&room=550e8400-uuid
Alur Autentikasi
1. Client kirim HTTP Upgrade request dengan ?token=...
2. Server validasi token via AuthClient::validate_token()
3a. Token valid   → upgrade ke WebSocket, kirim event "connected"
3b. Token invalid → HTTP 401, koneksi ditolak (tidak di-upgrade)
4. Token expired saat koneksi aktif → server kirim event "token_expired", tutup koneksi
5. Client refresh token via REST, lalu reconnect dengan token baru
⚠️
Token di query param — hati-hati log server

URL dengan ?token=... bisa muncul di access log nginx. Pastikan nginx dikonfigurasi untuk tidak log query string pada endpoint WS: log_format ws_format '$remote_addr "$request_uri_no_query"'. Atau gunakan token berumur sangat pendek (30 detik) khusus untuk WS handshake.

📦Message Envelope

Semua message WS (dari client maupun dari server) menggunakan envelope JSON yang sama.

Client → Server
{
  "type": "chat.send",
  "request_id": "req_uuid",  // client generate
  "payload": {
    "room_id": "uuid",
    "content": "Halo!"
  }
}
Server → Client
{
  "type": "chat.message",
  "request_id": "req_uuid",  // echo dari client
  "payload": {
    "message_id": "uuid",
    "sender_id": "uuid",
    "content": "Halo!",
    "created_at": "2026-06-09T10:00:00Z"
  }
}
Definisi Field Envelope
FieldTipeWajib?Keterangan
typestringSelaluFormat: {domain}.{action}. Contoh: chat.send, chat.typing, system.ping.
request_idstring UUIDSelaluClient generate untuk setiap message. Server echo-back di response. Berguna untuk korelasi ACK.
payloadobjectTergantung typeData spesifik per event type. Bisa null untuk event tanpa data (ping, ack).

🔁Reconnect Strategy

SkenarioAksi ClientAksi Server
Koneksi terputus (network)Exponential backoff: 1s → 2s → 4s → 8s → max 30s. Reconnect tanpa user perlu tahu.Tidak ada state yang perlu di-cleanup — stateless.
Token expired (system.token_expired)Refresh token via REST dulu, lalu reconnect dengan access token baru.Tutup koneksi dengan WS close code 4001 (custom: Unauthorized).
Server restart / deployReconnect otomatis dengan backoff. Fetch ulang history pesan yang terlewat via REST GET /chat/messages?after={last_id}.Kirim WS close code 1012 (Service Restart) sebelum shutdown.
Room tidak ada / akses ditolakTampilkan error ke user. Jangan reconnect otomatis.Tolak koneksi dengan HTTP 404 atau 403 saat handshake.
WS Close Codes
CodeArtiAksi Client
1000Normal closureTidak perlu reconnect
1001Going away (server shutdown)Reconnect dengan backoff
1012Service restartReconnect dengan backoff + fetch missed messages
4000Custom: Bad requestJangan reconnect, tampilkan error
4001Custom: UnauthorizedRefresh token, lalu reconnect

❌Error Handling

Error yang terjadi setelah koneksi terbentuk dikirim sebagai message biasa dengan type error.

// Error response dari server
{
  "type": "error",
  "request_id": "req_1",    // echo dari request client yang gagal
  "payload": {
    "code":    "MESSAGE_TOO_LONG",
    "message": "Pesan tidak boleh lebih dari 4000 karakter"
  }
}
Error CodeKeterangan
MESSAGE_TOO_LONGKonten pesan melebihi 4000 karakter
ROOM_NOT_MEMBERUser bukan member room yang dituju
RATE_LIMITEDTerlalu banyak pesan dalam waktu singkat (max 10 pesan/detik)
INVALID_PAYLOADFormat payload tidak sesuai (field wajib kosong, tipe salah)
UNKNOWN_TYPEEvent type tidak dikenal server

🏠Room / Channel

AturanDetail
Satu koneksi WS = satu roomClient buka koneksi WS baru untuk setiap room yang diakses. Tidak ada multiplexing dalam satu koneksi.
Room IDUUID v4. Format: pasangan user diurutkan secara deterministik: MIN(user_a, user_b) + "_" + MAX(user_a, user_b). Selalu room yang sama untuk dua user yang sama.
Histori pesanFetch via REST GET /api/v1/chat/messages?room_id={id}&before={cursor}&limit=30 sebelum konek WS. WS hanya untuk realtime update.
Offline messagePesan yang dikirim saat user offline disimpan di DB. Saat reconnect, client fetch pesan yang terlewat via REST dengan after={last_message_id}.

⚙️Implementasi Rust

// chat-service/src/interface/ws_handler.rs (sketch)
pub async fn ws_handler(
  ws: WebSocketUpgrade,
  Query(params): Query<WsParams>,  // { token, room_id }
  State(state): State<AppState>,
) -> Response {
  // 1. Validasi token SEBELUM upgrade
  let claims = match state.auth_client.validate_token(&params.token).await {
    Ok(c) => c,
    Err(_) => return StatusCode::UNAUTHORIZED.into_response(),
  };
  // 2. Upgrade ke WS — hanya jika token valid
  ws.on_upgrade(move |socket| handle_socket(socket, claims, params.room_id, state))
}

async fn handle_socket(mut socket: WebSocket, claims: AuthClaims, room_id: Uuid, state: AppState) {
  // Kirim konfirmasi koneksi
  send_event(&mut socket, "system.connected", json!({"user_id": claims.sub})).await;

  loop {
    tokio::select! {
      msg = socket.recv() => match msg {
        Some(Ok(Message::Text(text))) => handle_message(&mut socket, &text, &claims, &state).await,
        Some(Ok(Message::Close(_))) | None => break,
        _ => {}
      },
      update = state.broadcast.recv() => {
        // Push realtime update ke client
        send_event(&mut socket, "chat.message", update).await;
      }
    }
  }
}
