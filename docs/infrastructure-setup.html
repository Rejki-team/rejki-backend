Phase 1.5 — Infrastructure Setup

Docker, nginx & Container Setup

Seluruh infrastruktur lokal dan produksi dijalankan dengan satu docker compose up. Dokumen ini menjelaskan docker-compose.yml, dua Dockerfile (Rust dan Bun), serta dua konfigurasi nginx (dev dan prod).

docker-compose.yml
yaml docker-compose.yml 
services:

  # ── PostgreSQL ───────────────────────────────────────────────────────────
  postgres:
    image: postgres:17-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER:     ${POSTGRES_USER:-rejki}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-secret}
      POSTGRES_DB:       ${POSTGRES_DB:-rejki}
    volumes:
      - pgdata:/var/lib/postgresql/data
      - ./scripts/init-schemas.sql:/docker-entrypoint-initdb.d/init-schemas.sql:ro
    ports:
      - "5432:5432"       # expose ke host untuk development (dbeaver, psql)
    healthcheck:
      test:     ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER:-rejki}"]
      interval: 10s
      timeout:  5s
      retries:  5
    networks: [internal]

  # ── Redis ────────────────────────────────────────────────────────────────
  redis:
    image: redis:7-alpine
    restart: unless-stopped
    command: redis-server --save 60 1 --loglevel warning
    volumes:
      - redisdata:/data
    ports:
      - "6379:6379"       # expose ke host untuk redis-cli dev
    healthcheck:
      test:     ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout:  5s
      retries:  5
    networks: [internal]

  # ── rejki-app (Rust modular monolith) ────────────────────────────────────
  rejki-app:
    build: .
    restart: unless-stopped
    expose: ["8080"]   # tidak publish ke host — hanya nginx yang akses
    depends_on:
      postgres: { condition: service_healthy }
      redis:    { condition: service_healthy }
    env_file: [.env]
    environment:
      APP_ENV: ${APP_ENV:-development}
    volumes:
      - ./keys:/app/keys:ro   # JWT private key, dll
    healthcheck:
      test:     ["CMD-SHELL", "wget -qO- http://localhost:8080/health || exit 1"]
      interval: 15s
      timeout:  5s
      start_period: 10s
      retries:  3
    networks: [internal]

  # ── bun-notification-service ─────────────────────────────────────────────
  bun-notification:
    build: ./bun-notification-service
    restart: unless-stopped
    expose: ["9000"]   # health endpoint — tidak perlu akses dari luar
    depends_on:
      postgres: { condition: service_healthy }
      redis:    { condition: service_healthy }
    environment:
      DATABASE_URL:               postgresql://${POSTGRES_USER:-rejki}:${POSTGRES_PASSWORD:-secret}@postgres:5432/${POSTGRES_DB:-rejki}
      REDIS_URL:                  redis://redis:6379
      FIREBASE_SERVICE_ACCOUNT_PATH: /app/keys/firebase-service-account.json
      FIREBASE_PROJECT_ID:        ${FIREBASE_PROJECT_ID}
      SMTP_HOST:                  ${SMTP_HOST:-smtp.gmail.com}
      SMTP_PORT:                  ${SMTP_PORT:-587}
      SMTP_USERNAME:              ${SMTP_USERNAME}
      SMTP_PASSWORD:              ${SMTP_PASSWORD}
      EMAIL_FROM:                 ${EMAIL_FROM:-Rejki <noreply@rejki.id>}
      NODE_ENV:                   production
    volumes:
      - ./keys:/app/keys:ro
    healthcheck:
      test:     ["CMD-SHELL", "wget -qO- http://localhost:9000/health || exit 1"]
      interval: 15s
      timeout:  5s
      start_period: 15s
      retries:  3
    networks: [internal]

  # ── nginx ─────────────────────────────────────────────────────────────────
  nginx:
    image: nginx:1.27-alpine
    restart: unless-stopped
    ports:
      - "80:80"
    volumes:
      - ./nginx.dev.conf:/etc/nginx/conf.d/default.conf:ro   # ganti ke nginx.prod.conf di production
    depends_on:
      rejki-app: { condition: service_healthy }
    networks: [internal]

  # ── Cloudflare Tunnel (production only) ───────────────────────────────────
  cloudflare-tunnel:
    image: cloudflare/cloudflared:latest
    restart: unless-stopped
    command: tunnel --no-autoupdate run --token ${CLOUDFLARE_TUNNEL_TOKEN}
    profiles: [prod]   # docker compose --profile prod up
    depends_on:
      - nginx
    networks: [internal]

volumes:
  pgdata:
  redisdata:

networks:
  internal:
    driver: bridge

Dockerfile — rejki-app (Rust Multi-stage)

Multi-stage build dengan dependency caching layer — jika hanya source yang berubah (bukan Cargo.toml), Docker menggunakan cache layer dependency sehingga build berikutnya jauh lebih cepat.

StageBase ImageOutput
builderrust:1.82-bookwormBinary /app/target/release/rejki-app
runtimedebian:bookworm-slimFinal image dengan binary saja, non-root user rejki (uid 1001)
Dependency caching trick
dockerfile Dockerfile (excerpt — dep cache layer) 
# 1. Copy semua Cargo.toml tanpa source asli
COPY Cargo.toml Cargo.lock ./
COPY auth-service/Cargo.toml auth-service/Cargo.toml
# ... (semua crate)

# 2. Buat src dummy — cargo fetch dependency tanpa compile source asli
RUN mkdir -p auth-service/src \
    && echo "fn main() {}" > auth-service/src/main.rs

# 3. Compile dependency saja — di-cache selama Cargo.toml tidak berubah
RUN cargo build --release -p rejki-app 2>/dev/null || true

# 4. Copy source asli, touch main.rs agar cargo detect perubahan
COPY . .
RUN touch rejki-app/src/main.rs
RUN cargo build --release -p rejki-app
✅
Non-root user wajib

Runtime stage menjalankan binary sebagai rejki (uid 1001) bukan root. Volume ./keys di-mount :ro (read-only) untuk keamanan.

Dockerfile — bun-notification-service (Bun Multi-stage)
dockerfile bun-notification-service/Dockerfile 
# ── Stage 1: Install dependencies ────────────────────────────────────────
FROM oven/bun:1-alpine AS deps

WORKDIR /app
COPY package.json bun.lockb* ./
RUN bun install --frozen-lockfile --production

# ── Stage 2: Runtime ──────────────────────────────────────────────────────
FROM oven/bun:1-alpine

WORKDIR /app

# Non-root user
RUN addgroup -S rejki && adduser -S -G rejki rejki

COPY --from=deps /app/node_modules ./node_modules
COPY src/        ./src/
COPY migrations/ ./migrations/

# Direktori keys akan di-mount via volume
RUN mkdir -p /app/keys && chown -R rejki:rejki /app

USER rejki

ENV NODE_ENV=production

EXPOSE 9000

HEALTHCHECK --interval=15s --timeout=5s --start-period=15s --retries=3 \
    CMD wget -qO- http://localhost:9000/health || exit 1

CMD ["bun", "run", "src/index.ts"]
ℹ️
bun.lockb harus ada sebelum build

Jalankan bun install sekali di dalam bun-notification-service/ untuk menghasilkan bun.lockb. File ini harus di-commit agar --frozen-lockfile berhasil.

nginx.dev.conf — Development

Konfigurasi minimalis untuk development: proxy ke rejki-app:8080, WebSocket support, tanpa rate limit.

Swagger UI hanya di development. Saat APP_ENV=development, rejki-app menyajikan dokumentasi API interaktif di /swagger-ui (dokumen di /api-docs/openapi.json) — di-proxy apa adanya oleh nginx dev. Toggle ini otomatis dari APP_ENV di aplikasi, bukan dari konfigurasi nginx. Akses dev sebaiknya dibatasi (subdomain di belakang Cloudflare Access / SSH tunnel) — lihat VPS Deployment §10.
nginx nginx.dev.conf 
upstream rejki_app {
    server rejki-app:8080;
    keepalive 32;
}

server {
    listen 80;
    server_name _;

    access_log /var/log/nginx/access.log;
    error_log  /var/log/nginx/error.log warn;

    client_max_body_size 10m;

    # Health check tanpa log
    location = /health {
        access_log off;
        proxy_pass         http://rejki_app;
        proxy_http_version 1.1;
        proxy_set_header   Host            $host;
        proxy_set_header   X-Real-IP       $remote_addr;
        proxy_connect_timeout 3s;
        proxy_read_timeout    5s;
    }

    # WebSocket — URL mengandung ?token= query param, log DIMATIKAN
    location /api/v1/chat/ws {
        access_log off;  # PENTING: token di query string tidak boleh masuk log

        proxy_pass         http://rejki_app;
        proxy_http_version 1.1;
        proxy_set_header   Upgrade    $http_upgrade;
        proxy_set_header   Connection "upgrade";
        proxy_set_header   Host       $host;
        proxy_set_header   X-Real-IP  $remote_addr;

        proxy_read_timeout  3600s;
        proxy_send_timeout  3600s;
        proxy_connect_timeout 5s;
    }

    # REST API umum
    location /api/ {
        proxy_pass         http://rejki_app;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $http_x_forwarded_for;
        proxy_set_header   Connection        "";
        proxy_connect_timeout 5s;
        proxy_read_timeout    30s;
        proxy_send_timeout    30s;
    }

    # Semua path lain → 404
    location / {
        default_type application/json;
        return 404 '{"error":"NOT_FOUND","message":"endpoint tidak ditemukan"}';
    }
}

nginx.prod.conf — Production

Rate limiting tiga zona, structured JSON logging via $uri (bukan $request — menghindari query string di log), security headers, custom 429/502.

Tidak ada Swagger di production. Karena APP_ENV=production, rejki-app tidak mendaftarkan rute /swagger-ui maupun /api-docs/openapi.json (keduanya 404) — skema API tidak terekspos. nginx prod tidak perlu aturan khusus untuk memblokirnya; gating sudah dilakukan di aplikasi.
Rate Limit Zones
ZoneRateDigunakan OlehBurst
api_limit10 req/s per IPREST API umum /api/, WebSocket20 (REST), 5 (WS)
auth_limit3 req/s per IP/api/v1/auth/login|register|resend-otp5
strict_limit1 req/s per IPEndpoint sangat sensitif (e.g. forgot-password)2
JSON Log Format
nginx nginx.prod.conf (log_format) 
log_format json_combined escape=json
    '{'
        '"time":"$time_iso8601",'
        '"method":"$request_method",'
        '"uri":"$uri",'           # $uri bukan $request — tidak ada query string
        '"status":$status,'
        '"bytes":$body_bytes_sent,'
        '"duration":$request_time,'
        '"ip":"$http_x_forwarded_for",'
        '"ua":"$http_user_agent"'
    '}';
⚠️
Gunakan $uri bukan $request

$request menyertakan query string lengkap. Endpoint chat WebSocket menggunakan ?token=... — jika masuk log, token JWT bocor ke log aggregator. Gunakan $uri yang hanya mencatat path.

Custom Error Responses
nginx nginx.prod.conf (error pages) 
# 429 — rate limited
error_page 429 @too_many_requests;
location @too_many_requests {
    default_type application/json;
    return 429 '{"error":"RATE_LIMITED","message":"terlalu banyak request, coba beberapa saat lagi"}';
}

# 502 503 504 — upstream down
error_page 502 503 504 @upstream_error;
location @upstream_error {
    default_type application/json;
    return 503 '{"error":"SERVICE_UNAVAILABLE","message":"layanan sedang tidak tersedia"}';
}
