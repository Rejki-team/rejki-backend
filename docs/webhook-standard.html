Webhook Standard

Standar teknis untuk outgoing webhook dari rejki-backend. Mencakup signature (HMAC-SHA256), payload format, retry policy, dan event catalog. Dokumen ini menjadi acuan untuk implementasi webhook publisher di masa depan.

F3 Signature: HMAC-SHA256 Retry: 3× + Jitter Status: Standard
📋
Webhook Standard Overview

Dokumen ini mendefinisikan standar untuk semua outgoing webhook dari rejki-backend. Tujuan standardisasi:

  • Keamanan — Verifikasi integritas payload via HMAC-SHA256
  • Replay protection — Via timestamp + toleransi 5 menit
  • Reliability — Retry dengan exponential backoff + jitter
  • Idempotency — Setiap event memiliki event_id UUID v7 unik
  • Interoperabilitas — Format konsisten untuk semua event
🔐
Signature (HMAC-SHA256)

Setiap request webhook WAJIB menyertakan signature header untuk verifikasi integritas.

Header
http Request Headers 
X-Webhook-Signature: sha256=5a4b3c2d1e0f...
X-Webhook-Timestamp: 2026-06-22T10:30:00Z
X-Webhook-Idempotency-Key: 0191f8c0-1234-7abc-bdef-123456789abc
Content-Type: application/json
Algoritma Signature
text 
1. Concatenate: timestamp + "." + request body (JSON string, tanpa whitespace)
2. HMAC-SHA256 dengan secret key per subscriber
3. Encode hasil HMAC ke lowercase hex
4. Set header: X-Webhook-Signature: sha256={hex}
Verifikasi (oleh subscriber)
pseudo 
function verify_webhook(body, timestamp, signature_hex, secret):
    // Replay protection: toleransi 5 menit
    now = current_time()
    if abs(now - timestamp) > 5 minutes:
        return false  // reject expired

    // Hitung ulang signature
    payload = timestamp + "." + JSON.stringify(body)
    expected = HMAC_SHA256(payload, secret)

    // Constant-time comparison (cegah timing attack)
    return constant_time_compare(expected, signature_hex)
Secret Key Management
  • Setiap subscriber memiliki secret key unik
  • Secret disimpan di database atau env vars
  • Rotasi key: support multiple active keys (version prefix di signature)

Backoff Formula
python 
import random, math

def backoff_delay(attempt: int) -> float:
    # Exponential: 1 << attempt   =>  1, 2, 4, 8, 16, ...
    base = float(1 << attempt)   # 2^attempt
    jitter = random.uniform(0.8, 1.2)  # ±20%
    return min(base * jitter, 30.0)     # cap 30 detik
Response Codes yang Memicu Retry
  • 5xx — Server error (retry with backoff)
  • 429 — Rate limited (retry with longer backoff)
  • 408 — Request timeout (retry)
  • 2xx — Sukses (berhenti, jangan retry)
  • 4xx (selain 408/429) — Client error (jangan retry, subscriber error konfigurasi)

Contoh Implementasi (Rust)

Pseudo-code Rust untuk webhook publisher dan verifier.

Publisher — HMAC Sign
rust 
use hmac::{Hmac, Mac};
use sha2::Sha256;
use std::time::{SystemTime, UNIX_EPOCH};

type HmacSha256 = Hmac;

fn sign_webhook(body: &str, secret: &[u8]) -> (String, String) {
    let timestamp = SystemTime::now()
        .duration_since(UNIX_EPOCH)
        .unwrap()
        .as_secs()
        .to_string();

    let payload = format!("{}.{}", timestamp, body);

    let mut mac = HmacSha256::new_from_slice(secret)
        .expect("HMAC key length invalid");
    mac.update(payload.as_bytes());
    let signature = hex::encode(&mac.finalize().into_bytes());

    (timestamp, signature)
}
Verifier — Validate Signature + Replay Protection
rust 
fn verify_webhook(
    body: &str,
    timestamp_secs: u64,
    signature_hex: &str,
    secret: &[u8],
) -> bool {
    // Replay protection: toleransi 5 menit
    let now = SystemTime::now()
        .duration_since(UNIX_EPOCH)
        .unwrap()
        .as_secs();
    if now.abs_diff(timestamp_secs) > 300 {
        return false; // expired
    }

    // Recompute signature
    let payload = format!("{}.{}", timestamp_secs, body);
    let mut mac = HmacSha256::new_from_slice(secret).unwrap();
    mac.update(payload.as_bytes());
    let expected = hex::encode(mac.finalize().into_bytes());

    // Constant-time comparison
    expected == signature_hex
}
