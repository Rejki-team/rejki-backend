Phase 1.5 — Health Check & Graceful Shutdown

Health Check & Graceful Shutdown

Standar endpoint health check, format response, dan prosedur graceful shutdown untuk semua service Rejki Backend agar deployment zero-downtime dan load balancer bisa deteksi service yang tidak sehat.

Phase 1.5 All Services

🏥Health Check Endpoint

AspekStandar
PathGET /health — tidak menggunakan prefix /api/v1/, tidak memerlukan auth.
AksesPublik — nginx dan load balancer mengakses langsung tanpa header Authorization.
HTTP Status healthy200 OK — semua dependency up.
HTTP Status unhealthy503 Service Unavailable — minimal satu dependency kritis down.
Timeout responseMaksimum 5 detik. Jika DB check > 5 detik, return 503.
Di-log?Tidak — health check tidak boleh masuk application log (terlalu noisy). Konfigurasi di nginx: access_log off untuk path /health.

📦Format Response

Status Healthy (200)
{
  "status":  "healthy",
  "service": "auth-service",
  "version": "0.1.0",             // dari Cargo.toml
  "checks": {
    "database": "ok"
  }
}
Status Unhealthy (503)
{
  "status":  "unhealthy",
  "service": "auth-service",
  "version": "0.1.0",
  "checks": {
    "database": "error: connection refused"   // pesan singkat, tidak detail stack trace
  }
}
Field checksKeterangan
"database": "ok"Wajib ada di semua service. Lakukan SELECT 1 dengan timeout 3 detik.
⚠️
Jangan bocorkan detail error di response health check

Pesan error di field checks hanya boleh berupa deskripsi singkat: "connection refused", "timeout". Tidak boleh ada stack trace, query SQL, atau informasi internal lainnya — endpoint ini publik.

🛑Graceful Shutdown

AturanDetail
Signal yang ditanganiSIGTERM — signal default dari Docker/systemd saat stop container. Juga tangani Ctrl+C (SIGINT) untuk development.
Drain timeoutMaksimum 30 detik untuk request yang sedang berjalan selesai. Setelah 30 detik, shutdown paksa.
Health endpoint saat shutdownSetelah menerima SIGTERM, GET /health langsung return 503. Ini memberi tahu load balancer untuk berhenti kirim traffic baru.
New request saat shutdownDitolak dengan 503. Request yang sudah diterima sebelum SIGTERM tetap diselesaikan.
Log shutdownLog event: INFO "received SIGTERM, starting graceful shutdown" dan INFO "shutdown complete".

📋Urutan Shutdown

Urutan shutdown yang benar (penting — jangan dibalik):

1. Terima SIGTERM
2. Set flag "shutting down" → /health langsung return 503
3. Stop terima koneksi baru (close listener)
4. Tunggu semua in-flight request selesai (max 30 detik)
5. Tutup WebSocket connection aktif dengan close code 1012 (Service Restart)
6. Flush log buffer yang pending
7. Tutup DB connection pool (semua koneksi dikembalikan ke pool dulu)
8. Exit process dengan code 0
ℹ️
Kenapa DB pool ditutup terakhir?

Request yang sedang berjalan di langkah 4 mungkin masih butuh akses DB untuk menyelesaikan transaksi. Jika pool ditutup lebih awal, request tersebut akan error di tengah jalan dan data bisa setengah tersimpan.

⚙️Implementasi Rust

// rejki-app/src/main.rs
use std::sync::atomic::{AtomicBool, Ordering};
use std::sync::Arc;
use tokio::signal;

// Handler health check — sederhana, tidak perlu Arc
async fn health_handler(
  State(pool): State<PgPool>,
  State(shutting_down): State<Arc<AtomicBool>>,
) -> impl IntoResponse {
  if shutting_down.load(Ordering::SeqCst) {
    return (StatusCode::SERVICE_UNAVAILABLE,
      Json(json!({ "status": "unhealthy", "checks": { "database": "shutting down" } }))
    ).into_response();
  }
  let db_status = match sqlx::query("SELECT 1").execute(&pool).await {
    Ok(_)  => json!({ "database": "ok" }),
    Err(e) => json!({ "database": format!("error: {}", e) }),
  };
  let is_healthy = db_status["database"] == "ok";
  let status = if is_healthy { StatusCode::OK } else { StatusCode::SERVICE_UNAVAILABLE };
  (status, Json(json!({
    "status":  if is_healthy { "healthy" } else { "unhealthy" },
    "service": "rejki-app",
    "version": env!("CARGO_PKG_VERSION"),
    "checks":  db_status,
  }))).into_response()
}

// Graceful shutdown di main()
let shutdown_flag = Arc::new(AtomicBool::new(false));
let flag_clone = shutdown_flag.clone();

let server = axum::serve(listener, app)
  .with_graceful_shutdown(async move {
    signal::ctrl_c().await.ok();           // Ctrl+C (SIGINT)
    // Untuk SIGTERM di production:
    // signal::unix::signal(signal::unix::SignalKind::terminate())...
    flag_clone.store(true, Ordering::SeqCst);
    tracing::info!("received shutdown signal, starting graceful shutdown");
  });

server.await.expect("server error");
tracing::info!("shutdown complete");
pool.close().await;    // tutup DB pool SETELAH server selesai
