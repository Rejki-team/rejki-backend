Phase 1.5 — Configuration Standard

Configuration & Environment Standard

Standar penamaan environment variable, struktur file konfigurasi per environment, validasi fail-fast saat startup, dan katalog variabel wajib untuk semua service Rejki Backend.

Phase 1.5 All Services

🧭Prinsip

✅
Dokumen ini adalah Single Source of Truth untuk konfigurasi

Naming convention, prinsip fail-fast, dan katalog variabel wajib didefinisikan di sini. Dokumen lain yang menyebut environment variable merujuk ke standar ini: Infrastructure Setup (konteks Docker Compose) · VPS Deployment (konteks production) · Bun.js Service (konteks TypeScript).

Fail-fast on startupJika konfigurasi wajib tidak ada atau tidak valid, service harus langsung panic saat startup — bukan saat pertama kali config dipakai di runtime. Silent misconfiguration lebih berbahaya dari crash.
SCREAMING_SNAKE_CASE untuk semua namaSemua environment variable menggunakan format SCREAMING_SNAKE_CASE. Tidak ada mix case, tidak ada titik atau dash.
Prefix service untuk var spesifikVariable yang hanya berlaku untuk satu service menggunakan prefix service. Variable shared (DB URL, JWT key) tidak perlu prefix.
.env hanya untuk developmentFile .env hanya diload di environment development. Staging dan production menggunakan environment variable sistem — tidak ada file .env di server.
.env.example selalu sinkronSetiap kali ada variabel baru, .env.example wajib diupdate di commit yang sama. .env.example tidak boleh berisi nilai nyata — hanya placeholder.

💥Fail-Fast Validation

Semua validasi config dilakukan di main.rs sebelum server mulai menerima request.

Jenis ValidasiCaraContoh Error
Variabel wajib tidak adaenv::var("KEY").expect("KEY tidak di-set")thread 'main' panicked: APP_ENV tidak di-set
Nilai tidak validParse ke tipe yang benar, panic jika gagalAPP_PORT=abc → panicked: invalid port: abc
File tidak ditemukanfs::read_to_string(path).expect("JWT_PRIVATE_KEY_PATH tidak dapat dibaca")panicked: JWT_PRIVATE_KEY_PATH tidak dapat dibaca: No such file
DB tidak bisa dikoneksiPgPool::connect(&url).await.expect("gagal connect ke DB")panicked: gagal connect ke DB: connection refused
Nilai enum tidak validMatch APP_ENV ke enum, panic jika tidak dikenalpanicked: APP_ENV tidak valid: 'prod' (harus: development/test/staging/production)
✅
Panic saat startup = aman. Panic saat runtime = berbahaya.

Service yang gagal start karena missing config akan segera terdeteksi saat deployment. Service yang start lalu crash di tengah request karena missing config adalah bug yang lebih buruk — request user hilang, data mungkin setengah tersimpan.

⚙️Implementasi Rust

// common/config/src/lib.rs — struct konfigurasi yang di-share
pub struct AppConfig {
  pub env:      AppEnv,
  pub port:     u16,
  pub db_url:   String,
}

#[derive(Debug, Clone, PartialEq)]
pub enum AppEnv {
  Development, Test, Staging, Production,
}

impl AppConfig {
  pub fn from_env() -> Self {
    let env_str = std::env::var("APP_ENV").expect("APP_ENV tidak di-set");
    let env = match env_str.as_str() {
      "development" => AppEnv::Development,
      "test"        => AppEnv::Test,
      "staging"     => AppEnv::Staging,
      "production"  => AppEnv::Production,
      other => panic!("APP_ENV tidak valid: '{other}' (harus: development/test/staging/production)"),
    };
    Self {
      env,
      port:   std::env::var("APP_PORT").unwrap_or("8080".into())
                .parse().expect("APP_PORT harus berupa angka valid (0-65535)"),
      db_url: std::env::var("DATABASE_URL").expect("DATABASE_URL tidak di-set"),
    }
  }
}

// rejki-app/src/main.rs
#[tokio::main]
async fn main() {
  // Load .env HANYA di development
  if std::env::var("APP_ENV").unwrap_or_default() == "development" {
    dotenvy::dotenv().ok();   // ok() = tidak panic jika .env tidak ada
  }
  let config = AppConfig::from_env();    // ← panic disini jika config tidak valid
  common_tracing::init_tracing(&config.env);
  // ... rest of main
}
